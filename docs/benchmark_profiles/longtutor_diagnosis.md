## 这是哪个子评测

- 家族 LongTutor 面向长程辅导场景，本仓库实现了三个子评测：证据定位、本页的学生状态诊断、以及长历史下的教学动作选择。
- 三者是一条链：先找得到证据，才谈得上判断状态，再谈得上选对动作。本页是中间环节，也是学习者画像能力目前唯一的主证据。
- 与"错因归因"的区别在于时间尺度：归因是从这一次的作答解释这次为什么错，本页是从整段历史判断这个学生整体会什么、不会什么。

## 出处与背景

- 官方仓库只提供 pipeline 脚本，本仓库自行移植为可复现的 adapter，绝对分不与原论文对照。
- **协议对齐（2026-11-06）**：预测端复刻官方 `eval_ai_tutor.py` 发布版默认配置（`use_feature=False, use_teach=False`）——常驻官方 system prompt（含四类诊断 Schema 定义与策略映射）、官方合并 JSON 调用（同一轮回答 memory 问答+诊断+教学，本子评测取 `diagnosis` 字段）、历史取最近 200 条按官方纯文本拼接、采样温度 0。此前的旧协议只发一句 "Choose exactly one diagnosis: ..."，无 Schema 定义；官方评测同样默认不提供统计特征数值，该点现状已一致。

## 任务与判分

- 给定长交互历史，模型把学生的知识状态归入四类之一，取 macro-F1。
- 取 macro-F1 而非准确率，因为类别分布不平衡。

## 局限与注意

- **区分度（13 号，v7/R28，分析日 2026-11-02）**：four-category knowledge-state diagnosis macro-F1 在当前面板 n=8、均分 2.622、SD=0.677，范围 1.539–3.437，未触发 ceiling 或 low_variance。低分现象需要认真对待，但不能脱离下面四条注记直接外推为所有模型的稳定结论。**注：该面板数字产生于协议对齐之前的旧协议运行。**
- 一是类别不平衡的严重程度：多数类基线的准确率是 0.506，而模型只有 0.35–0.44——也就是说模型的判断还不如"永远猜最常见的那一类"。
- 二是金标的产生方式：由特征决策矩阵加人工修订得到，不是独立盲标，金标本身带有构造痕迹。
- 三是旧协议的系统性偏差（2026-11-06 审计）：旧协议下 8 模型在 gold=Recall Failure 的 212 题中全军覆没 185 题（预测该类仅 0.8%–6.3%，gold 占 21.2%），主因是旧 prompt 无 Schema 定义且不引导模型回溯历史中的掌握证据；协议对齐后面板数字需重新解读。
- 四是协议敏感度与端点漂移（2026-11-07/09 官方协议重跑）：MiniMax-M3 新旧协议逐题一致率 99.9%（不敏感）；deepseek-v4-pro 46.5%、Qwen3.8-27B 58.1%、MiniMax-M3.1-Flash-Preview 42.5%（高度敏感，官方 Schema 定义使 RF/TD 预测大幅上升）。控制实验（旧 prompt×当前端点）证实 **M3.1-Flash-Preview 端点在 2026-10-22 前后被上游换版**（同 prompt 自一致率仅 64.1%），preview 类模型的面板历史存在不可比风险。新协议下 M3.1-Flash macro-F1 0.429、Recall Failure 召回 30.7%，与旧数字（0.31/近零）不可比。
- 这一项同时作为错因归因的弱信号计入，但那不是它的主场。
