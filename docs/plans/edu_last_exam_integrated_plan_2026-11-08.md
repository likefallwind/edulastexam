# Edu Last Exam：教育场景 × Agent 原子能力方案

版本：proposal v1.0 · 2026-11-08

本方案汇总 2026-11-08 的仓库复核、近两年文献核验、已有 34 个 challenge 题目的审计，以及对长周期测量方式的讨论。它不是一个已经确定的长对话 benchmark，而是先按教育场景寻找仍然不稳定的能力，再用 Agent 原子能力解释这些失败，最后选择合适的题目形态。它是下一阶段的研究与出题方案，不表示正式题集已经冻结，也不表示当前模型失败率已经完成验证。

## 一、要建立什么样的 Benchmark

Edu Last Exam 要测的不是“模型是否会回答一类教育问题”，而是：

> 在具体教育场景中，教育 Agent 能否依据真实证据完成可核验、具有教育意义的工作；对于确实需要连续教学的场景，还要能在后续证据和行动后果下保持判断与行为的一致性。

一个有资格进入 Edu Last Exam 的 case，至少要满足四点：

1. 有真实教育用途：批改、诊断、辅导、命题、备课、教学材料或学习路径中的具体工作。
2. 有明确的成功条件：正常的教师或教育专业人员能够依据题目提供的信息完成判断或交付物。
3. 失败有教育后果：错误会造成误评分、错误反馈、错误教学路径、错误材料或错误测量，而不是只违反格式偏好。
4. 能够复核：关键结论可由学生作品、题目约束、学科规则、运行结果、后测或专家标注追溯。

因此，题目难度不能来自冷僻知识、隐藏条件、损坏图片、任意格式要求或把多个无关小题机械拼接起来。难度应来自教育工作的真实组合：理解学生证据、维护状态、选择动作、生成材料、核验结果并在新证据出现后修正。

## 二、分类标准：教育场景 × Agent 原子能力

今天讨论的两个分类标准都要保留，但用途不同。

### 2.1 教育场景维度：我们让 Agent 做什么

第一维是面向用户和教育工作的任务分类。

**A. 学生作品理解、评价与反馈**

- 手写、图形、公式和跨页作品的忠实还原；
- 首错定位、过程正确性、合法非标准解和错误传播；
- 部分评分、复核、申诉和反馈事实性；
- 作品内伪指令、错误外部分数和无依据抗辩的处理。

**B. 学生状态诊断与适应性教学**

- 从多次作业和对话中判断掌握、误解、偶发失误和提示依赖；
- 选择苏格拉底提问、提示、讲解、练习、支架撤除或路径调整；
- 维持教学目标，处理插问、拒答、持续错误和新证据；
- 在后续证据出现时更新诊断，而不是坚持旧判断。

**C. 长周期教学闭环**

- 初始诊断；
- 连续教学动作；
- 学生新反应；
- 状态更新；
- 作业或材料；
- 延迟后测、迁移和保持。

这是 Edu Last Exam 的核心增量。当前 LongTutor、MathTutorBench、P07 等主要能覆盖其中的局部环节，不能直接等价为完整纵向教学。

**D. 高质量教育内容与教学产物**

- 教案、练习、评分标准和针对学生状态的补救材料；
- 图文、公式、演示步骤和跨页内容的一致性；
- PPT、SVG、HTML 或交互科学演示的事实正确性、可执行性和学习目标对齐；
- 根据学生反馈修订材料，并验证修订是否真正解决问题。

这里的问题不是“模型完全不会写教案”，而是一次性生成的内容是否忠实、连贯、适龄、可执行，并且确实服务于给定学习目标。

**E. 命题、测评和学习路径设计**

- 题目可解性、答案唯一性和信息充分性；
- 认知要求与学习目标对齐；
- 诊断性干扰项和练习设计；
- 难度、先修关系和学习路径判断；
- 修订题目后，原来的测量含义是否仍然成立。

**F. 公平性、鲁棒性和可信交付**

- 无关身份标签是否改变评分、反馈或机会分配；
- 是否把合理便利与学习能力混为一谈；
- 作品、外部参考、学生说明和模型指令发生冲突时，是否依据有效证据；
- 交付物能否渲染、运行、复查和被另一位教育者接手。

F 不是一个笼统的“公平总分”，而是贯穿 A–E 的配对控制与审计维度。

## 三、测量形态：先由能力决定，不预设全是长周期

教育场景和原子能力确定后，再选择最能识别该能力的测量形态。并非所有方向都需要长周期：一次作品诊断可能适合单轮；连续支架适合 Session；延迟保持和学习路径才需要 Episode。把一段历史对话放进一个 prompt，只能测“基于历史的回顾性判断”，不能自动变成长周期。

### 3.1 三个层级

| 层级 | 定义 | 作用 |
|---|---|---|
| Turn | 一次输入和一次输出 | 保留当前单轮题，测局部证据理解和局部决策 |
| Session | 3–8 次“Agent 动作 → 学生反应”循环 | 测连续动作、条件反应，以及必要时的状态更新和教学决策 |
| Episode | 多个 Session，之间有任务、时间间隔和后测 | 在构念需要时测计划、遗忘、迁移、保持和前序错误的后果 |

第一版不需要直接做到 30 天。对于确实需要持续状态的方向，建议先做 6–10 个 Session case，再做 3–5 个 Episode case。其他方向可以保持 Turn-level 或静态产物验收，等证据表明长周期会改变结论后再扩展。

### 3.2 只有必要时引入学生状态和环境

是否维护学生状态由 case 的构念决定：

- Turn case 可以只测一次作品理解、评分、命题判断或教学材料事实正确性，不需要隐藏学生状态；
- Session case 只有在“下一步学生反应依赖 Agent 当前动作”时，才需要一个可分支的学生回应机制；
- Episode case 只有在题目要测延迟保持、迁移、学习路径或前序决策后果时，才需要跨 Session 的持久状态。

对需要环境的 case，模型看到的是历史、学生回答、草稿、行为和允许调用的教学工具。环境根据动作返回下一次学生反应。学生环境采用“真实轨迹校准 + 可重复分支模拟”的混合方式：固定真人轨迹用于现实性检查，规则或知识追踪环境用于分支、控制难度和重复运行。纯粹让另一个大语言模型自由扮演学生，不能作为唯一环境，因为它容易过度配合、任意改变状态或被语言套路绕过。

模拟环境中的后测只能支持“模拟环境中的教学结果”结论；真实学习增益需要另做真人研究，不能从 Agent 交互分数直接推出。

### 3.3 需要长周期时的关键转折

只有进入 Session/Episode 的 case 才需要刻意设计这些有教育意义的转折，而不是只增加轮数：

- 学生猜对，但没有真正掌握；
- 学生在提示下答对，但独立完成仍失败；
- 两个学生答案相同，错误原因不同；
- 学生已经掌握，Agent 却继续代做；
- 新证据与旧诊断矛盾，Agent 需要主动修正；
- 当下表现改善，但延迟迁移失败；
- 生成的材料看起来完整，却没有解决学生的具体错误。

## 四、先判断哪些教育领域仍然表现不好

这里要先做领域盘点，再决定正式题目。原方案中的方向全部作为候选池保留，但不预先假设每个方向都能进入 Last Exam，也不预先规定长周期是主轴。

### 4.1 候选教育场景

**场景一：学生作品理解、评价与反馈。**

优先做：

- 跨页手写/图形/公式的忠实理解；
- 首错、过程正确性、合法非标准解和错误传播；
- 评分标准、外部参考和申诉证据的核验；
- 从多次作业中区分稳定误解、偶发错误和提示依赖。

这条赛道的优势是证据可追溯、专家容易复核，也能直接接上仓库已有的评分和 LongTutor 结果。

**场景二：学生状态诊断与适应性教学。**

优先做：

- 诊断到提问/提示/练习的落实；
- 支架增加、撤除和独立迁移；
- 插问后的流程恢复；
- 新证据出现后的状态更新；
- 延迟后测和迁移。

这里是否需要长周期，要由具体能力决定：状态重建可以先做长历史 Turn，支架调整需要 Session，保持和迁移才需要 Episode。

**场景三：高质量教育内容和教学产物。**

优先做：

- 给定教材、学习目标、学生状态和课堂限制，生成教案/练习/评价；
- 检查目标—活动—练习—评价是否闭环；
- 检查跨页图文、公式、标签、单位和科学规律；
- 渲染并运行 HTML/SVG/交互演示；
- 根据学生反馈修订材料，再用后续任务验证修订。

这一方向通常先做材料级 Turn 或执行级 case；只有当材料需要根据学生反馈反复修订时，才进入 Session 或 Episode。

**场景四：命题、测评和学习路径设计。**

先做少量高质量 case，重点关注题目效度、诊断性干扰项、先修关系和目标对齐。不要把没有真实学生数据支撑的精确难度预测或 IRT 参数作为第一版硬金标。

**场景五：公平性、鲁棒性和可信交付。**

采用配对反事实和交付审计，贯穿前四类场景。它不单独构成一个分数，而是检查身份标签、外部参考、工具失败和交接条件是否改变实质结论。

### 4.2 领域筛选标准

每个候选领域先建立一张证据卡，至少记录：

- 近两年是否有直接行为测量，而不是只有旧模型或主观判断；
- 仓库现有 benchmark 是否出现跨模型、跨题目的共同失败；
- 是否有强模型成功反例，以及失败是否依赖模型版本、提示或工具；
- 失败是否具有教育后果，而不只是格式或风格差异；
- 是否能建立稳定的人类金标和自动/人工验收；
- 失败能否归因到一个或几个原子能力；
- 适合 Turn、Session、Episode 中的哪一种测量形态。

据此将方向分为三档：

1. **优先验证**：已有直接失败证据，教育意义和判定条件都清楚；
2. **候选补强**：教育意义明确，但当前模型证据不足，需要复测或补充材料；
3. **暂不进入核心**：只有旧结果、代理指标、主观偏好或无法稳定判分。

只有第一档和经过复测进入第一档的第二档，才进入正式题目设计。

### 4.3 当前的优先验证顺序

基于目前仓库结果和近两年研究，建议先验证以下四组，而不是直接扩充全部方向：

1. **长历史状态诊断、适应性支架和自查**：仓库已有 LongTutor、MathTutorBench、P07 等共同失败信号；需要继续区分回顾性判断、短程交互和真正延迟教学。
2. **学生作品和过程评价**：首错、错误原因、合法非标准解、手写/图形证据和评分一致性，具有较好的证据可追溯性。
3. **高质量教育内容与多媒体产物**：教案、PPT、图文解释和交互演示的正确性、目标对齐、跨页一致与可执行性；不能只测“像不像教案”。
4. **命题效度、诊断性练习和学习路径**：保留为高价值候选，先确认当前模型是否仍有稳定的实质失败，再决定是否进入首版主集。

公平性和可信交付先作为上述方向的配对控制与审计维度，暂不把它们压成一个独立总分。

## 五、下一步准备怎么干

### 第一步：完成教育领域—原子能力证据矩阵

先正式复核两类已有材料：

- **近两年文献**：只保留 2024-11 以后、能够定位任务、模型、协议和失败行为的研究；把“模型可能做不好”的讨论和直接实验结果分开；
- **本仓库已有实验**：复核 `docs/atomic_ability_mapping_v7_2026-11-02.md`、`data/mapping_measurement_model_v7.json`、`reports/atomic_ability_rebenchmark_v7_R28_snapshot_20261103/12_benchmark_portfolio_review.md`、`reports/frontier_selection_v1/validation_report.md`、现有 challenge v2 题目和 GLM/MiniMax 试跑，区分正式结果、代理证据、探索性结果和人工复核项。

再把原方案的候选方向、仓库 benchmark、近两年论文、已测模型和成功反例放入统一矩阵。矩阵的行是教育场景，列只使用 P01–P21；单元格记录直接测量、辅助证据、失败案例、判分条件和证据强度。先找出“哪几个场景—P 能力组合确实存在当前共同短板”，再决定题目。

这一阶段不新增正式题，不通过题目设计反过来制造失败。

本阶段的整理结果见：[Edu Last Exam 证据矩阵](../evidence/edu_last_exam_evidence_matrix_2026-11-09.md)。矩阵确认前，不进入正式数据集设计。

### 第二步：冻结构念和题目资格

先把每个候选方向写成任务卡，明确：教育用途、模型可见信息、允许工具、成功条件、关键错误、可接受替代方案、证据来源和判分方式。把“直接测量”“辅助探针”“控制题”“探索题”分开，避免把文献代理指标直接当成 Edu Last Exam 总分。

旧 GPT-4 数学失败、简单格式注入或已经被强模型普遍解决的例子不再作为核心难题。

### 第三步：为入选领域选择题目形态

对每个入选单元格分别决定：

- 用 Turn 测量证据还原、评分或产物事实正确性；
- 用 Session 测量连续提问、支架调整、反馈修订或工具执行；
- 用 Episode 测量延迟保持、迁移、学习路径和长期状态。

长周期只是其中一种测量协议，不是所有题目的共同外壳。

### 第四步：把现有单轮题改造成合适的 case

保留当前 34 个题作为历史 pilot 和 Turn-level anchor，不把它们全部改造成长周期题。优先选择：

- 09、12、13：转成“初始诊断—教学动作—学生反应—状态更新”；
- 14、19、20：转成“生成材料—渲染/运行—学生使用—反馈—修订”；
- LongTutor、MathTutorBench、P07：作为状态诊断、脚手架和自查的起始机制，不直接声称完整纵向能力。

先构造少量但完整的复合 case，而不是继续增加独立短题。

### 第五步：按需实现 StudentEnv 和统一日志

只有被选为 Session/Episode 的方向才实现离线、可重复的 StudentEnv。它至少记录：

- case 和环境版本；
- 初始隐藏状态；
- Agent 每次动作；
- 学生环境返回的观察；
- Agent 的状态更新和计划；
- 材料、工具调用、渲染和运行结果；
- 即时后测、迁移题和延迟后测；
- 每个 checkpoint 的金标和判分依据。

先支持固定 seed 和有限动作/回应库，再增加自然语言分支。环境故障、工具失败和模型能力失败必须分开记录。

### 第六步：建立专家金标和人类基线

每个 case 需要作者参考解、领域专家复核、至少一种合理替代方案和关键错误样例。动态 case 还要由专家确认：

- 当前证据确实足以支持某个判断，或者明确属于不可识别情境；
- 学生环境的反应与真实轨迹相符；
- 多种教学动作是否都合理；
- 哪些错误属于关键失败，哪些只是风格差异。

冻结后再让未参与出题的专业人员完成一部分 case，得到人类首次成功率、耗时、求助和分歧记录。不能只拿作者能解作为人类基线。

### 第七步：做小规模协议验证

1. **单轮—Session 对照**：同一学生问题先测一次回答，再测 3–8 轮交互，确认难度是否来自状态维护而非题面变化。
2. **静态历史—分支环境对照**：只对状态诊断和适应性教学方向比较把历史一次性给出和让模型逐步获得新证据，区分长上下文能力与长周期决策能力。
3. **即时—延迟后测对照**：检查模型是否只让学生当下答对，还是能形成迁移和保持。
4. **静态产物—执行产物对照**：比较只看文本/代码和实际渲染、运行、学生使用后的结果。

这些验证先用少量模型和少量 case 完成，目标是检验协议可识别性，不是立即发布模型排名。

### 第八步：用模型面板做发现和复测

发现阶段可以使用当前可用模型寻找失败机制，但正式题必须和发现模型隔离。至少保留一个未参与题目发现的模型家族作为留出测试。每个模型固定模型版本、系统提示、工具、上下文和预算，并记录缓存、失败重试和解析状态。

当前 GLM-5.3-Flash 的试跑只说明原有 34 个题中仍有少量可观察错误和若干需要人工验证的产物问题，不能支持正式的 Last Exam 结论。后续应优先测试复合 case，而不是继续用更多简单单轮题稀释错误率。

### 第九步：冻结题集和发布结论

最终报告分开给出：

- Turn、Session、Episode 三个层级的结果；
- 诊断、教学动作、状态更新、产物验证和后测结果；
- 关键失败率与普通错误率；
- 人类基线和专家分歧；
- 模拟环境证据与真实学生证据；
- 发现集、冻结核心集和未经模型筛难的迁移集。

只有当人类可完成、关键判分稳定、失败具有教育意义、留出模型仍出现共同失败，并且不能通过简单增加上下文或改提示消除时，才把对应 track 称为 Edu Last Exam。否则保留为 pilot 或 candidate，不为了名字强行压低通过率。

## 六、最终的项目判断

Edu Last Exam 最值得做的主线不是“找一道很刁钻的题难住模型”，也不是把所有题都做成长对话，而是先找到当前教育场景中的真实共同短板，再构造能把短板稳定测出来的任务。对需要持续状态的方向，最终可以构造这样的教育闭环：

> Agent 必须忠实理解学生证据，形成可修正的学生状态，选择合适的教学动作，生成或修改可用材料，并在延迟的独立证据中证明自己的判断是对的。

这条主线既继承了原方案中学生作品、评分、教学目的、教案/PPT、交互产物和公平性方向，也使用仓库已有 P01–P21 来解释失败。它能解释为什么模型在某些单轮回答上表现很好，却仍可能无法完成具体教育工作；也能把“长对话”放回它应该所在的位置：只有在某个教育构念确实需要连续证据和后果时，才使用相应的 Session 或 Episode 协议。
