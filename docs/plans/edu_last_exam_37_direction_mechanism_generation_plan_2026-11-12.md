# Edu Last Exam 37 方向机制驱动数据生成计划

日期：2026-11-12。状态：当前生产计划；蓝图与生成队列为候选设计，不是冻结 benchmark。

## 1. 决定

下一轮数据生成以既有 01–37 方向为工作全集。每个方向都必须先回答“这个教育任务为什么可能让 Agent 生成不好”，再把回答转成可实例化的题族生成规则。已有模型错例不再决定一个方向能否进入造数流程。

主流程固定为：

`原始方向构念 → 任务要求与机制分析 → 必要输入条件 → 材料和情境变化轴 → 题族与反事实 → gold/rubric/oracle → 离线校验 → 审核与试跑`

这条路线替代 V2 第一批设计中“只有已定位 V1 失败的机制才继续繁殖”的后续生成政策，但不否定第一批五题族及其运行证据。V2 第一批保留为部分方向的已有样本，后续批次使用新的 item ID、protocol 和隔离运行目录。

37/37 是本轮**机制蓝图和候选生成计划**的覆盖目标，不等于最终冻结集必须平均覆盖 37 个方向，也不要求每个方向使用相同题数。

## 2. 每个方向必须完成的机制分析

机制分析不是复述“正确做法应该是什么”，而是形成可以被数据检验的解释：

1. **任务要求**：Agent 必须作出什么教育判断、教学行动或真实交付，错误会造成什么具体教育后果。
2. **可能捷径**：在缺乏足够证据时，Agent 可能依赖什么表面特征、默认假设或流程省略，例如把最终答案当掌握证据、把外部标签当作品事实、把计划文本当真实交付。
3. **失效条件**：哪些输入证据、未知状态、条件冲突、时间顺序或环境变化会使该捷径产生可观察错误。
4. **证据基础**：分别标明文献条件、原始任务结构、历史模型错误和作者离线检查；没有模型失败证据时仍可依文献和任务结构形成待验证假设。
5. **证伪与边界**：哪些成功反例或合理替代行为会反驳过强的机制解释，哪些子结论无法由当前任务测量。

“机制”是生成和检验的工作假设，不是对模型内部心理过程的断言。一次失败不能证明普遍困难，一次通过也不能取消该方向的后续数据生成。

## 3. 从机制到数据的生成规则

每个方向的机器可读蓝图位于 `data/edu_last_exam_mechanism_generation_v1/direction_blueprints.json`，至少包含：

- `task_demand` 与 `education_consequence`；
- `mechanism_analysis`：捷径、失效条件、表面流畅为何不足及证据类型；
- `required_conditions`：必须可见的证据、必须保留的不确定性或状态，以及输入充分性；
- `observable_signals` 与 `critical_errors`；
- `material_axes` 与 `context_axes`：用于生成真正不同材料和教学情境，而非只换姓名、数字或措辞；
- `family_plans`：题族、任务视图、生成说明、依赖版本、改变量、不变量、预期差异和 oracle；
- `oracle_and_limits`：确定性检查、语义量尺、原生协议或人工审核需求，以及未测子结论；
- 可选 `historical_examples`：历史成功或失败只作支持、反驳、控制或复核线索。

题族内的反事实应改变影响教育判断的关键条件，并保持其他材料不变。正确作品、等价解、no-op、合理申诉和中性提示等成功控制与目标困难同时设计。关联方向可以帮助解释跨构念题，但不增加该方向的主覆盖数。

## 4. 生产与晋级顺序

### 4.1 蓝图阶段

01–37 全部形成蓝图和至少一个题族生成计划。生成队列按方向组织，不按历史失败数量决定哪些方向出现。

### 4.2 Authoring 阶段

按蓝图创建 cards、独立材料、authored gold、rubric、controls 和 runtime。优先复用现有单轮、续轮、分支、workspace、artifact 和 media 环境；只有现有环境无法表达目标构念时才扩展 adapter。

被测面板模型不得生成 canonical items。合成材料必须标明合成身份，不冒充真实学生、真实课堂或原生 benchmark 数据。

### 4.3 离线验证与审核

每批必须先通过确定性验证，再考虑 API 试跑。检查输入充分性、gold 隔离、分支一致性、文件或媒体资产、oracle 正反例、参考解和导出哈希。之后进行独立教师、学科、安全或视觉审核，具体审核类型由方向决定。

### 4.4 试跑与修正

试跑用于检验机制是否产生预期行为，不用于反向改写原题以制造失败。模型失败先区分题目/gold 缺陷、输入或运行问题、judge 问题和真实目标机制错误；模型成功则可成为控制或回归证据。

发现集、后续修订集和未经模型筛难的迁移集分开保存。冻结需要相应的人审、协议校准和多模型证据，不能由蓝图覆盖数或单次试跑替代。

## 5. 阻塞与覆盖口径

蓝图覆盖不等于可运行覆盖。路线矩阵中的原生环境、真实学生数据、长期学习结果、安全人评或媒体缺口继续有效：

- `ready_to_author`：可以依据现有材料和明确边界创作候选，不代表已经 authored 或 executable。
- `blocked`：仍须写机制与生成计划，但缺少的资产、环境或评分条件必须列入 `blockers`，未解除前不得声称可运行或冻结。
- 对 bounded synthetic candidate，必须写出它能够测量的子机制和不能替代的原始结论。例如短对话不能证明长期学习效果，模拟学生不能证明自然课堂效度，静态转写不能证明视觉识别。

报告分别给出蓝图、计划题族、ready/blocked、主方向覆盖及后续 authored/reviewed/tested/frozen 状态，不合成跨构念总分。

## 6. 与既有管线的关系

- `direction_index.json` 和完整证据清单：固定 37 方向的原始身份和研究范围。
- 37 份 source card：提供文献、原始任务、条件映射与来源限制。
- `direction_mechanism_map.json`：提供已有机制种子和候选 benchmark 线索，继续用于发现，不改写成另一套分类。
- route matrix：提供来源路线、oracle、控制、晋级门槛和阻塞状态。
- full-coverage 与 V2：提供已 authored 的探索实例和模型证据，不是后续生成的准入名单。
- item-selection queue：继续处理既有候选的复核与筛选，位于生成、审核和试跑之后。

新增构建器只负责蓝图校验和生成队列，不调用模型 API，不复制现有 runner 或 judge。

## 7. 本次验收

1. 01–37 每方向恰好一个主蓝图，mechanism ID 和 family ID 唯一。
2. 每方向均有机制、生成条件、材料/情境轴、至少一个带对照的题族计划、评分和限制。
3. 没有历史失败引用的蓝图也能通过；历史证据存在时仍校验身份和角色。
4. blocked 方向不会被自动计入 ready 或可执行覆盖。
5. V2 第一批题面、item、prompt 和 runtime 内容哈希保持不变；历史报告不被修改。
