# Edu Last Exam：完整研究与实验方案

版本：proposal v1.0 · 2026-11-07 · 状态：方案，尚未验证正式题集难度。

建议项目定位：**Edu Last Exam: Expert-Validated Challenges for Educational Agents**。第一版范围明确限定为 STEM 教育中的学生原作诊断、评价材料与科学教学产物；动态教学作为独立探索模块。

本方案依据近两年文献复核、现有 12 题审计，以及用户补充的原方案。研究依据见[近两年重审报告](../../reports/research/edu-last-exam-two-year-reassessment-2026-11-07.html)。本文件是方法与执行计划的源文档，对应 HTML 从本文件生成。文中的题型是设计原型，不是已写好、已通过专家审查或已证明困难的正式试题。

## 1. 目标、研究问题与可以宣称的结论

要建立一个经过专家验证的挑战集：**对应真实教育工作，信息充分、结果可核验、专业人员通常能够完成，而多数当前强 Agent 在正常工具和充分运行条件下仍难以完成。**

困难应存在于理解学习者证据、评价推理、保持测量效度、形成科学上正确的教学产物及其整合过程。需要跨步骤协同才能完成的真实任务，可以构成有效难度；不能为降低分数，把互不相关的小任务串联起来。

本项目回答四个问题：

1. 当前强 Agent 还在哪些有教育价值的任务上共同失败？
2. 这些失败在换系统、增加运行预算、允许正常工具后是否仍然存在？
3. 失败来自感知、学科推理、学生证据理解、教学设计还是执行核验？
4. 给出可靠转写、关键证据、专家规格或更好的执行框架后，哪些失败能得到修复？

第一版的结论范围是“在明确任务、系统与预算下的教育工作完成能力”。它不直接证明教师可被替代、学生一定学会、长期学习增益或教育全领域覆盖。成功率很低可以是结果，但不是题目质量的证明。

**Last Exam 是需要实验支持的发布定位。** 达到第 10 节门槛前，公开表述保留 pilot / candidate；不能先认定名字成立，再通过改变判分压低结果。全员失败题可以保留，无须为模型排名人为加入中等难度题。容易对照另报，不用来稀释或抬高主分。

## 2. 对用户原方案的继承与调整

用户补充的原方案包含 19 类文献线索、批改配对电池、真实手写三轨、教师意图 replay、关键决策点、实测难度分层、图文交互验收和公平性反事实。它比现有 12 题保留了更多真实任务结构。不能把 pilot 的纯文本简化归咎于原方案完全排除了多模态与交互。

主要调整是：**部署重要性与前沿难度分开排序；先保留原例困难，再筛选原创题；把输入充分、判分有效与完整 Agent 条件加入入选流程。**

| 原方向 | 新方案位置 | 必须改写的地方 |
|---|---|---|
| 批改抗操纵、无依据抗辩、外部分数锚定 | 贯穿 A 赛道的条件对照；真正难例可入核心 | 先判断评分/反馈是否实质正确。允许纠正错误初评；不把保持原分一概当正确 |
| 严格/宽松 prompt 敏感性 | 系统稳健性诊断实验 | 区分语气变化与评分政策变化。含“不给部分分”的 prompt 已改变实质规则，不能当纯措辞扰动 |
| 真实手写三轨 | 保留并升为 A1 核心候选 | 原图与可靠转写配对；既测证据还原，也测后续判断，避免只用 OCR 字符错率代替教育错误 |
| 教师意图与固定学生脚本 replay | C 扩展及控制 | 固定脚本可能与 Agent 实际回复不相容；只有分支有效的轨迹才能评交互。流程漏项须确实破坏用途 |
| 关键教学决策点、长历史诊断 | C 扩展；A 中保留证据利用 | 允许证据不足、追问和更新判断。不能将“事实不撤回”理解为永不纠正先前错误 |
| 反馈针对性 | A 的任务结果与次级指标 | 根据错误依赖关系给反馈；并非每道题都有唯一“首错”或唯一教学策略 |
| 命题内容有效性 | B1 核心候选 | 验证可接受答案、构念与反馈依据；普通选项格式缺陷作为控制 |
| 难度、DOK/Bloom、IRT | 分开研究 | 自报层级不是金标；群体难度和 IRT 依赖真实学生数据及估计条件，不强塞进单题硬判分 |
| 图文与交互产物验收 | B2/B3 核心候选 | 保留运行、几何、科学规律检查，同时验收它是否服务于给定学习目标 |
| 标签与公平性反事实 | 贯穿对照，不合成一个公平总分 | 固定作业质量与任务条件。合理的无障碍支持可改变表达方式；观察到群体差异不自动构成因果歧视证据 |

特别需要改写两条原来的硬规则：

- “无理由反对不得比请求复查提分更多”适合做配对、重复运行后的条件效应分析，不适合作为单次确定性金标。两次复核可能发现不同的真实错误；先检查改变是否有证据，再估计平均差异。
- “反馈不得跟随错误告知分数”应落实为事实性评价与诊断不能被错误分数带偏。仅检测正负语气不足；若任务要求解释既定分数，须明确授权核查和纠正该分数，避免相互冲突的任务要求。

手写“三轨”具体化为：①原图→模型转录，测保真；②专家忠实转录→模型诊断，测后续推理；③原图→完整批改，测端到端。专家转录保留学生原来的数学错误，不能将其修成正确解。转人工/弃答同时报告覆盖率与正确性，避免全部弃答看起来安全。读取失败不能当学生交白卷。

既有 12 题保留为历史 pilot。其可用部分用于解析、基础指令与控制检查；争议题先隔离，不直接扩成正式题，不把“修改金标后应该多少通过”当成已有结果。现有 adapter 的判分身份、缓存和数值门槛问题在后续实现阶段修复并进行针对性回归。

## 3. 第一版范围与任务构成

### 3.1 两条核心赛道

**A：忠实诊断与修复学生原作。** 输入学生已经做过的工作；输出有证据支撑的评价、错误解释或修订。必须能区分真正错误、合法另解和由前错传播的结果。

**B：修订与交付可信的教育内容和科学产物。** 输入教学目标、既有材料和必要的学生证据；输出可实际运行或使用、学科上正确、测量解释成立的材料。

首版优先数学、物理、统计、编程等可独立核验的领域，覆盖中学至大学基础阶段。专业挑战可以来自高水平教学工作，但不能通过冷僻学科知识或竞赛难度独自承担“教育难度”。语言保持材料原生中文/英文，分别报告；翻译版本属于同一案例家族。

**C：主动获取证据后的教学决策。** 单列探索，不计入第一版核心总分。它的角色是检查教学决策是否能被可靠测量，为后续动态教学版本建立证据。

### 3.2 规模与独立性

| 集合 | 拟定规模 | 作用与边界 |
|---|---:|---|
| 原例复核池 R | 18 个来源案例 | 验证论文失败在当前完整 Agent 下是否还存在；不作为原创主分 |
| 原创开发集 D | 24 个独立案例家族 | 调整任务定义、环境、验收器和诊断对照，可反复修改 |
| 候选池 | 由产出率决定 | 用发现系统筛选，所有版本、筛除原因与调用次数留档 |
| 冻结核心 H | 首版最低 60 个独立家族 | A/B 原则上各约一半，每条至少 20 个；至少三个不同失败机制各有 10 个案例。质量不达标时不凑配额 |
| 匹配控制 K | 20 个控制条件 | 含正常正确作品、易修错误、明确充分证据；不计挑战主分 |
| 未经模型筛难的迁移集 T | 20 个新家族 | 按冻结的构建规则产生，测试机制迁移；与筛选过的 H 分开报告 |
| C 探索集 | R 中 4 个起步；最多扩至 12 个 | 检验可识别性与评审一致性，不以数量承诺其能进入正式版 |

案例家族由共同原作、原题、学习者材料、关键环境和参考实现共同界定。换数字、语气、姓名、语言、图片颜色或增加申诉不是新的独立题。多个变体和多次运行不能虚增 N。

核心中应包含有挑战性的正确非标准解或有效产物审计，避免“题题有错”的捷径。普通正确材料放入 K。若正确作品上的困难样本不足，明确报告覆盖缺口，不能强塞易题或将正确作品改坏。

若只建成一个可信赛道，就发布限定范围的 track/pilot；不以很窄的数据声称覆盖全部教育工作。

## 4. 核心题型设计卡

以下是任务结构示例，不是最终题面，也没有“已经很难”的实测结论。正式题目、作业和完整答案依仓库规则放入 `private/`。

### A1. 跨页原作的证据还原与诊断

- **输入：**可清楚阅读的真实作业图片、完整题目和常规课程要求；包含续写、箭头、撤回草稿或相邻题，但不人为遮挡关键内容。
- **任务：**还原目标作答的有效步骤，判断需要反馈的问题，把关键判断定位到原页及区域。
- **有意义的难点：**批改学生实际保留的工作；不能把划掉的尝试算作最终错误，也不能补写学生没提供的理由。
- **通过：**关键证据归属和诊断成立；对真实歧义合理保留判断。允许等价转录和不同区域表示，不用像素框完全一致判失败。
- **验收：**证据锚点检查＋表达式核验＋教师双评；原图与转写均可追索。
- **对照：**可靠人工转写、清楚版式、无撤回草稿版本。
- **淘汰：**专家也读不清；题号/材料缺失；只因坐标格式失败。工具解决后若已普遍通过，则作回归控制。
- **来源起点：**HG-Bench 案例及可授权原始作业；其完整数据尚未公开，不将它作为项目唯一依赖。

### A2. 非标准推理、错误传播与部分分

- **输入：**学生原解、任务、课程允许使用的结论、合理的部分分规则；覆盖合法另解、边界条件遗漏、错误抵消和前错传播。
- **任务：**判断学生自己的推理；指出独立错误及影响，保留有效部分，给出有依据的反馈或评分。
- **有意义的难点：**标准解不相似不等于错误；结果正确不保证过程有效；一个错误也不意味着后续所有方法都错。
- **通过：**正确非标准解不受误伤，实质错误有反例或论证，独立错误和传播结果区分合理；分值在专家确认的允许范围内。
- **验收：**CAS、枚举、反例和必要的证明审查；自然语言与形式化表达的对应另查。Lean 编译失败不能直接当数学错误。
- **对照：**相近的正确/错误解；只修正早期错误后的版本；标准正确解；允许不同的正确修订路径。
- **淘汰：**困难完全来自刁钻学科题或细碎扣分规则；金标不接受合法省略/另解；专家对核心正确性长期无共识。

### A3. 学生代码的复合错误与可执行修复

- **输入：**真实学生程序、完整规格、可用环境与公开测试；可包含修复首错后出现的逻辑错误，或已有样例全过但存在规格内反例的程序。
- **任务：**运行、定位、复验并修复；交付代码与修改依据，解释学生原算法的问题。
- **有意义的难点：**分清已证实错误、后续才出现的错误和修复引入的新缺陷；不能以通用重写代替对学生原作的诊断。
- **通过：**错误指控有代码位置和触发证据；修订满足规格且未新增关键问题；能解释与原思路的关系。允许多个合理修复方案，不规定任意修改行数上限。
- **验收：**沙箱执行、差分/性质/回归测试、规格内隐藏输入；教师审查解释和思路保留。错误标签集合不作为唯一 gold。
- **对照：**单一语法错；修掉首错后已正确；结构相似的正确程序；仅在规格外失败的“伪反例”。
- **淘汰：**禁止执行才能难；缺少输入范围；运行环境损坏；只剩普通算法求解且不需要理解学生工作。
- **来源起点：**PyMETA 多错误子集，先做工具增强复测。

**教育特异性入选条件：**必须有由课程学习目标、任务中明确的允许方法、学生已完成的正确步骤或具体教学用途决定的评价/反馈决策，并单独验收。例如修订代码相同，但对两个不同原作应保留和纠正的概念不同；不能仅以修完程序通过测试为完成。若删除教育条件后任务实质不变，归入工程对照。课程限制须有教学理由，不能为禁用容易解法而临时添加。

### B1. 保持测量目标的题组、评分与反馈修订

- **输入：**学习目标、已有题组、评分/反馈规则、学生作答及教师计划采取的行动；可包含合法另解被误扣、答案不唯一、干扰项无法唯一指示误概念等问题。
- **任务：**审查并修订题目、答案和评分；重新处理受影响的学生记录，说明哪些教学结论仍成立。
- **有意义的难点：**修完文字后仍测原目标；不能通过降低目标推理要求或更换知识点规避问题，也不能把模糊证据强分成心理标签。允许消除与目标无关的阅读负担或歧义，即使实际作答难度因此下降；确需保持难度时另给明确要求及证据。
- **通过：**学科答案有效；合法学生答案得到接受；反馈可回溯作答证据；修订保持目标或明确揭示无法兼得的条件。
- **验收：**独立求解/枚举、未见学生答案、目标映射的教师审查；提供题目渲染和提交组件，避免重复开发平台。
- **对照：**无效题/有效题配对；目标保持但数值变化；给出专家修订规格后的实现。
- **淘汰：**只修选项长度等显眼格式问题就全过；用未告知偏好定义“好题”；没有真实学生数据却强判精确难度或 IRT 参数。
- **来源起点：**TeachArena 修题任务作方法和可行性参照；正式主集采用独立新材料。

### B2. 图、式、解释之间的科学一致性

- **输入：**教学目标、现有几何/物理/统计图及解释、必要的学生错误证据；提供所有决定性约束。
- **任务：**判断材料是否误导，并交付一致的图示、推导和解释；可要求对合法参数变化仍成立。
- **有意义的难点：**文字算对却画错、换表示后悄悄改变了条件、标签或单位误导概念理解。
- **通过：**关键几何关系、坐标/单位、图示与文本一致；不同正确绘图风格均可接受；解释针对已观察的问题。
- **验收：**从 SVG/图形数据提取约束并核验，再人工检查可见图；不以参考截图像素相似度替代科学正确性。
- **对照：**给出正确图只修解释；给出专家图形规格；文字版独立求解；正确但外观不同的产物。
- **淘汰：**输入缺约束；美观或布局喜好决定失败；只是一般画图任务，缺少明确教育用途。

### B3. 学生可以操作的科学实验与检测材料

- **输入：**现有演示或模板、课程目标、少量学生解释、合法参数域；提供通用界面组件和可靠计算工具。
- **任务：**修订或制作可运行演示，安排能检验目标概念的活动和检测题；最终交付物要可独立验收。
- **有意义的难点：**参数、数值、动画、文字和检测题要表达同一科学关系，并回应学生实际混淆。
- **通过：**核心科学关系成立、交互真实改变相应状态、反馈/检测题与目标一致。不得靠漂亮截图或计算结果正确掩盖错误教学含义。
- **验收：**浏览器执行＋独立数值/几何 oracle＋未见合法参数＋教师审查。随机模拟使用统计容差和多种子，不能要求单次样本恰好等于理论值。
- **对照：**专家规格→实现；正确产物→定位并修改教育问题；通用代码 Agent；提供正确计算组件后的表现。
- **淘汰：**主要失败是安装依赖/CSS/平台操作；评分器只检查固定 DOM；教学目标实际上不参与设计决策。

两种具体候选结构：

1. **折射实验修订：**学生把角度参照线混淆；验收数值、法线、射线、临界角与全反射的关系及检测题。明确光学模型，避免用材料密度替代折射率。所有概念边界在题目中规定，不能靠冷僻模型假设造难。
2. **SD/SE 采样演示：**学生会计算标准误，却将其解释成个体离散程度；验收总体/样本/样本均值分布的区别、样本量改变时的行为及迁移问题。重新采样必须真实发生，不能把同一组点缩放冒充。

这两种结构本身可能很容易；只有工具增强复测和专家验证后才决定保留。

### 跨 A/B 的条件变化：参考依据、申诉和标签

复用同一原材料，交叉改变：正确/有误参考解、有/无新证据申诉、礼貌/强硬语气、与评分无关的身份标签。模型明确被授权核验参考依据。

主要看实质裁决是否跟随有效证据，是否保留其他独立扣分理由；不以道歉、复述某句话、语气一致或无条件不改分判通过。变体属于同一家族，配对效应和失败类型单独报告。

## 5. 动态教学扩展 C 的具体协议

第一阶段测**主动诊断与决策**，不宣称自由对话教学效果。

1. 给初始学生作业、目标与证据目录；允许存在真实的信息不足。
2. Agent 可查相关历史、选一个诊断任务、请求学生解释，或暂缓判断。
3. 首版使用人工验证的有限证据/回应库，公开可选探测项的 ID、含义和访问方式；每项有确定材料。自然语言请求仅作为接口便利，不能成为隐含匹配考试。映射失败记为接口问题；库外但有效的探测方案由专家另评，不能直接算诊断错误。不得让 LLM 即兴编造学习者状态。
4. 检查是否提出能区分假设的探测、采纳反证、更新判断并采取有依据的行动。
5. 多种合理行动均可接受；不可识别时，“证据不足＋有效取证方案”可以通过。泛泛追问或永久拒绝判断不能自动拿满分。

每例在运行前证明：允许信息与预算中存在充分取证路径，或明确标为不可识别情境。不得把证据库没有提供的材料当成 Agent 应当猜出的事实。报告证据访问成功率和诊断结果，分别处理接口故障与能力失败。

建议两种原型：同样答对但理由不同的学生，下一步如何区分；学生反复说不懂时，如何识别知识错误、表述障碍或任务设计问题并调整行动。后者须有可观察支持，不能靠隐藏人格/诊断标签设 gold。

若扩展到任意多轮对话，用标准化真人角色测试检验执行，或另行验证学生模拟器的分支与评分稳定性。模拟学生说“懂了”、模拟知识状态上升，均不计真实学习成功。需要学习增益主张时，另做真实学生研究：对照条件、基线、无辅助未见后测，长期主张再增加延迟保持与迁移测量。

## 6. 取材、专家与判分验证

### 6.1 来源与作者机制

每例标明三种来源之一：真实教育材料 R、基于真实材料的可追索转换 T、教师/领域专家设计的专业挑战 C。模型生成的证明不能冒充真实学生作业。

从公开原例和可授权现实案例发现机制；原创阶段以独立材料重建任务，不做同义改写和换数字扩充。原例 R 池与原创核心 H 分开，注明生成/辅助作者及模型家族。依仓库流程出卡、编写、导出、自检，不调用被测面板批量命题；AI 协助编写不能替代领域专家审查。

投稿入口只要求现实场景、原材料、AI 错误输出、影响和可接受结果；评测团队负责构念、任务包、环境和验收。教师不需要自行设计 JSON schema 或原子能力标注。

### 6.2 每题的专家质量关

每题须有作者参考解、独立专家复核及可接受替代方案。关键判断和原材料存在未解决歧义时，暂不进入核心。

专家分别检查：输入是否足够；正常工具下是否能完成；失败是否影响真实评分、反馈、测量或科学教学；哪些约束是用途所必需；哪些只是表达习惯；是否可以通过简化交付物绕过目标。

没有标准答案的教育偏好不能强制二值化。可以规定明确教学任务，但不得用未给出的教师偏好或某历史案例的唯一成功策略作隐藏条件。

### 6.3 人类基线与“作者能解”的区别

冻结 H 后，由未见参考解、未参与该题制作的对应岗位专业人员完成：60 个案例每题至少一人，随机 20% 再由另一人独立完成。保留所有首次结果，包括失败、耗时和求助。覆盖多个参与者，记录专业背景和任务分配，避免单一作者承担所谓人类基线。

人类和 Agent 获得相同任务信息、资源与验收规则，允许相同类别工具。产物任务如果人类采用教师＋开发者协作，要报告团队人数与人时，不能称普通教师单人完成。预算条件先校准再冻结，不能给人类无限时间却把 Agent 限制为一次短回复。

发布门槛采用人类首次成功率至少 90%、相应不确定性下界至少 80% 的建议政策；报告区间方法和人员复用带来的相关性。不能删掉人类失败题后宣称专家 100%。若发现任务无效，按统一无效题程序处理所有系统。

### 6.4 验收器也必须被测试

每题必须测试：作者正确解、至少一种合理替代解、关键错误交付物、外观接近但语义错误的交付物。正确解不能因措辞/实现不同被拒绝，错误产物不能靠答案泄漏、固定输出或只满足可见表面检查通过。

确定性核验优先检查数学/规格/运行事实；教师盲评判断确实需要专业语义的部分。定性关键判决采用双人盲评及仲裁；LLM 可辅助提取或预判，不能作为未经校准的唯一最终判据。报告分歧和关键误判，不只给总体一致率。

金标、隐藏测试、参考实现与 Agent 的文件/工具环境隔离；隐含测试只能检查已经公开说明的要求。模型输出、作业内指令不能修改评估规则。修判分器后复用原始预测统一重评；仅当输入或环境变化影响生成时，才需要重新生成。

## 7. Agent 面板、工具与预算

### 7.1 评测对象

评测单位是“模型版本＋Agent 实现＋系统提示＋工具＋资源预算”。正式面板至少六个完整系统，覆盖至少四个模型家族；三者参与发现，三者作为留出，至少一个留出家族未参加发现。

留出意味着其正式结果从未用于改题、调验收器或选择 H。出题辅助模型所属家族也应披露，不能把同家族系统当完全独立的证据。

至少包含通用强 Agent 和面向代码/工具的强实现，不能只用最方便调用的 API 代表 Agent。MiniMax、智谱可参加面板或比较组，但不能单凭它们失败满足入选条件。具体版本在执行前依据当时可用能力和独立外部证据确定并冻结；本方案不假定现在列出的模型名到执行时仍是最强。

### 7.2 两种可解释的比较

- **主实验：完整系统比较。** 各系统保留合理能力与原生工具，环境资源与任务要求明确，记录差异；结论指向系统，不归因于模型参数本身。
- **机制实验：统一执行框架。** 在支持的模型上给相同工具接口和提示，帮助分析模型与框架差异；不替代完整系统主测。

正常工具包括终端、编程与科学计算、浏览器、图片裁剪/OCR、课程资料及必要文档检索。支持多次运行、调试和自查。给产物任务提供通用脚手架，避免把依赖安装错误当教育能力缺陷。

对公开旧原例，明确答案暴露风险。正式原创集可允许正常文档检索；隔离参考答案与验收文件，不以禁用一般工具防止系统做对。任何网络范围约束都需说明必要性、与现实使用差异，并单报开放工具条件。

### 7.3 预算与结束条件

原例阶段实测正常完成成本；正式标准预算建议以每例最多 60 分钟的可用工作时间为起点，高预算为同条件 3 倍。最终数值由正常控制任务和专家可解性校准，必须在留出测试之前冻结。记录实际耗时、模型费用、工具时间、上下文限制和请求数，不能只报预算上限。

遵守仓库政策：不人为设置模型 `max_tokens` 上限；供应商固有限制单独记录。主预算不额外限制为一次模型调用。超时是该预算下未完成，单独标记资源因素；网络故障、服务失败、环境损坏另记基础设施异常，不伪装为教育错误。

所有重试从干净状态开始，随机顺序；不把前次反馈或隐藏判分结果传给下一次独立运行。基础设施重试按预声明规则执行，不挑最好的一次冒充首次结果。

高预算实验是干净环境中的独立启动，不是接着失败轨迹续跑；标准/高预算尽量交错执行并锁定同一服务版本。每题高预算一次只支持整体预算敏感性分析，不能替代标准三次的重复可靠性。按案例配对报告增益与区间，不以两个点估计断言增加预算无效。

优先完成 E0–E3；E1 是每阶段前置质量关。E4/E5 的样本与条件在观察正式成绩前确定，避免只选择支持某种解释的失败。E6/E7 随正式版完成；E8 不阻塞 A/B 合格时的限定范围发布。

至少四种关键对照应保留：

1. **原图→可靠转写：**定位感知与后续推理的差异。
2. **原题独立求解→评价学生原作：**区分不会解题和误读学生思路。
3. **给原始证据→给专家确认的相关证据：**检查检索/整合瓶颈，注意后者是诊断性 oracle，不能当真实部署成绩。
4. **教学目标与学生材料→专家完整规格：**若只有后一条件能做好产物，提示设计/诊断环节的重要性；配对改善不是单一机制的完整因果证明。

所有对照须保持其余信息与预算尽量一致，记录哪些因素同时发生变化。

对确实依赖学习者证据的题，还可提供同等学科难度、不同学习者证据的配对条件，检查评价或材料是否作出有依据的变化。不能仅凭两段输出不相同就声称适配有效。若去掉教育目标后任务实质完全不变，应重新审查其教育特异性；一般工程失败单列，不让它独自承担核心集难度。

## 9. 主指标、判分与统计边界

### 9.1 主指标

每个独立案例预先规定少量不可缺少的教育结果。只有会破坏评分、反馈、测量解释或科学教学用途的错误触发任务失败。记录其证据，允许不同正确解和有效交付路径。

主分为每系统的**实质任务完成率**：先对同一案例的独立运行求平均，再对案例家族等权平均。正式 H 每家族指定一个冻结的主任务；变体在诊断实验单报。A/B 分赛道公开，综合数字只按预先固定权重汇总。

不定义“整套 60 题必须全对才算 Agent 通过”。这会把单题能力与重复可靠性混为一谈，也容易制造全系统零通过的戏剧性数字。

### 9.2 同时报告的结果

- 核心完成率及按案例家族重采样的不确定性区间；主要看留出系统，发现系统明确注明被用于筛题。
- 三次运行全部成功、至少一次成功的案例比例。后者是通过事后验收得到的乐观覆盖率，不等于 Agent 能自己选择正确答案。
- 正确原作误伤、实质错误漏检、证据归属、修复有效性、科学一致性及关键失败类型。
- 基础设施异常、模型拒答、格式问题、预算耗尽、任务不成立分别计数。
- 预算、成本、时延、人工评审覆盖与分歧。

有合理格式但语义错误仍失败；仅格式不合接口时优先以预声明、确定性的解析恢复，保留原文。不能借助知道 gold 的模型把坏答案修成好答案。

### 9.3 不做的统计推断

同题 0/3 成功，在独立同分布二项假设下，成功概率的单侧 95% 上界仍为 `1 - 0.05^(1/3) ≈ 63.2%`。三次运行用于观察波动，不能宣布该题“稳定不会做”。多次重试、同题变体不视为独立案例。

六个挑选出来的强系统不是全球 Agent 的随机样本；只能宣称冻结面板中的结果。数据经过挑战筛选，分数不代表日常教育工作的失败率。跨系统和任务类别的关联、同一专家多次作答都需说明，不能套用完全独立样本结论。多重统计比较如用于显著性结论，需要额外控制；不以事后 p 值决定保留题目。

T 的 20 家族只提供初步构建迁移证据，三个系统跑它也不能称 60 个独立迁移案例。发现明显失效应报告；小样本低分不支持精确概率断言。所有主运行次数预先锁定，成绩临界时不得反复追加直到跨过门槛。

## 10. “配得上 Edu Last Exam”的建议发布门槛

以下是**项目预先承诺的严格政策**，不是文献给出的通用自然分界。正式执行前冻结；看到结果后不能放松政策而仍保留原结论。

表中的 20%/30%/40% 是观测成绩政策，不等于相应真实成功概率的高置信上界；所有区间随分数公开。发现系统存在选题偏差，三个留出系统才承担未参与筛选系统上的验证结论。

| 门槛 | 建议要求 | 不达标时怎么处理 |
|---|---|---|
| 教育价值与有效性 | 每题有明确使用者、教育目标、真实后果、充分输入及可独立审查的成功依据；关键 gold 分歧全部解决 | 退回修改或列争议，不算模型失败 |
| 独立规模与覆盖 | 至少 60 个有效独立家族；A/B 各至少 20；至少三个机制各至少 10；真实材料/转换/专业挑战来源公开 | 发布限定 track 或 pilot，不凑题量 |
| 专家通常可解 | 独立专家首次完成率≥90%，相应 95% 不确定性下界≥80%；保留首次失败 | 先检查预算、材料与验收，不通过删除人工失败来美化结果 |
| 留出系统与当前强度 | 六个完整强系统、至少四家族、三个未参与设计的留出系统；至少一个留出家族全新 | 数据只能支持开发面板结论 |
| 标准预算共同难度 | 至少 5/6 系统完成率≤20%，且包括三个留出系统；所有系统≤30%；同时公开区间 | 如实发布更易的挑战/pilot；不能按留出结果删掉被做对的题 |
| 重试后仍有明显困难 | 上述五个系统的三次乐观成功覆盖率≤40% | 说明题目可被重试较常解决，研究可靠性而非宣称普遍不会 |
| 预算复验 | 全 H 六系统三倍预算；至少 5/6（含三个留出）完成率≤30%，所有系统≤40% | 限定为预算条件下困难，不能作充分资源下共同边界宣称 |
| 正常条件和验收可信 | 冻结前控制任务可完成；正式 K 每系统完成率建议≥85%；无未处理的关键判分错误和基础设施混分 | 修复环境/协议；不可静默排除表现异常的强系统 |

同时检查分赛道是否掩盖简单方向。若低总分完全由单一赛道造成，另一赛道应另报，不能把总体困难归给全部方向。子类型样本不足时报告描述统计，不做稳定排名或泛化断言。

不要求排序区分度：六个系统都很低可以成立。也不要求困难永远持续；后续模型解决某些题就是有价值的进展。版本冻结后保留这些题及历史结果，另建新版本，不暗中删题维护低分。

## 11. 防止选题过拟合、污染与评估捷径

### 11.1 开发、筛选、验证分离

1. D 用于改任务蓝图、输入结构和验收规则。
2. 候选池可按预声明规则使用三个发现系统筛难；披露筛选分母、命中率、修改次数及筛除理由。
3. H 冻结后，三个留出系统的结果只用于验证，不再指导删题、改 rubric 或挑最佳版本。发现系统的低分存在选择偏差，不能当独立发现。
4. T 在读取留出结果前，按冻结规则从新材料产生并锁定，不经模型筛难，单报迁移结果。它检验机制能否在新材料中自然出现，不能与挑战筛选 H 混合。
5. 一旦使用留出结果调整构建规则，这轮结果降为开发证据，原留出系统转为开发系统。新版本若仍主张未参与设计系统上的验证，须重新指定满足留出条件的系统；仅增加独立新案例只能支持构建迁移结论，不能恢复原系统的留出资格。

候选筛难规则建议：至少两个发现系统在重复运行中出现经核实的实质错误，且不是同一个环境故障；这只决定候选优先级。正式难度门槛只在冻结后判断，筛选规则不能保证留出系统也失败。

### 11.2 公开政策

仓库 `private/` 名称是历史遗留，现行政策允许并要求正式自建题提交公开。本方案不把它描述为保密测试库，也不默认改变用户的公开决定。

首次验证尽量在正式发布题库之前完成；保存题目首次暴露时间、来源是否已经公开、模型训练/检索暴露风险。发布之后的成绩属于已公开题条件。需要刷新当前前沿结论时，补充独立新材料和新版本；不能仅凭旧公开题声明无污染。

若将来希望持续私有评分，需要单独确定新的发布策略和存储方式；不作为本方案默认依赖。

### 11.3 发生争议时

保留模型原始输出与版本。若确认 gold、环境或验收器错误，公开修订记录，对受影响全部系统统一处理；判分器修复优先重评已有结果。无效题不能只从某个系统的分母中消失。

核心有效家族数跌破发布门槛时，降为候选版本或使用预封存、与系统结果无关的补充流程，并生成新版本。不得为了维持低分只补难题、只删容易题而不披露。

## 12. 分阶段执行、产出和停止条件

| 阶段 | 工作 | 可审阅交付物 | 继续条件 |
|---|---|---|---|
| P0：原例侦察 | R=18；A 8、B 6、C 4 为初始搜集目标，缺材料时标缺口不强替；两强系统各两次 | 来源台账、原始失败复核、专家判断、当前运行轨迹、逐例淘汰理由 | 至少找到两个有教育价值且工具后仍有实质失败的机制；否则改变来源/方向 |
| P1：原创方法开发 | D=24；A/B 各约 12；构建作者参考、替代解、验收负例；三发现系统各两次 | 任务规格 v0、原型环境、judge 校准、失败机制与控制报告 | 至少 12 个独立家族达到有效性和可复测要求；难度不足时不扩量 |
| P2：建立候选池和冻结 H | 根据 P1 的有效产出率扩大；三发现系统筛选；冻结 H/K/T、预算和面板 | 60 个有效核心、20 控制、20 迁移、版本哈希、预先声明的分析计划 | 所有材料与验收可运行，具备专家及留出系统执行条件 |
| P3：正式实验 | E1–E7；标准、三倍预算、留出系统、专家首次作答与分层诊断 | 完整 summary、原始轨迹、产物、人工评审、统计区间、来源及污染说明 | 按第 10 节判断命名和结论，不能反向改门槛 |
| P4：发布与后续版本 | 发布限定 claim、任务包、验收说明、审计结果；持续保存已解决案例 | Benchmark 文档/数据、代码与环境、结果页、错误更正机制、研究稿 | 新模型解决则记录进展；新困难另起版本 |

P0/P1 为投入控制阶段：没有可信困难就停止扩量。无需一次把全部平台和六个正式系统搭好。

候选筛选先做至多 120 个新家族，根据产出率决定是否继续至 300 个上限；每家族固定三个发现系统各两次，不因快达到“全错”而无限重试。结构性改题退回开发并记录版本；客观材料/环境修复最多安排一次全发现面板重测，额外成本单列。到上限仍不足 60 个合格家族，就收窄范围或发布 pilot，不能无限筛选同一种漏洞。

## 13. 运行数量、预算与人员安排

### 13.1 可以先算清的实验量

| 部分 | 运行数 |
|---|---:|
| R 原例：18×2 系统×2 次 | 72 |
| D 开发的首轮：24×3×2 | 144 |
| 候选筛选 | 候选数 C×3×2；修改后的额外运行单列 |
| H 标准正式：60×6×3 | 1,080 |
| H 高预算：60×6×1 | 360 |
| K 控制：20×6×1 | 120 |
| T 迁移：20×3 留出×1 | 60 |
| 正式 E2/E3/控制/迁移合计 | 1,620 |

上述不包含必要的原协议复现、E4/E5 消融、C 扩展、异常重试、作者与人类基线。候选筛选和开发运行不能悄悄复用为留出正式证据。

候选池大小用实测有效产出率 q 估算：`C ≈ 60/q`。若 q=0.2–0.5，需要约 120–300 个候选家族，这只是条件情景，不是已知产出率。不能承诺写 60 题就得到 60 道可信难题。

在 300 个候选上限下，首轮筛选最多 1,800 次；若每例都触发一次必要的客观修复重测，则最多再加 1,800 次。原例、开发和正式实验已列部分合计 1,836 次，**不包含候选筛选**，不得把 1,620 次正式运行误称全部项目费用。实际很可能在 P0/P1 就停下或调整方向。

API/工具预算用 P0 的每类任务实测成本估计：`Σ(运行数 × 该系统该条件每次平均费用)`，另报尾部成本和失败重试。未获得真实调用成本前不编造人民币报价。时间预算同样以实测中位数及高分位数计算，而非把所有运行都当一次短问答。

### 13.2 人员与时间假设

最小角色：研究负责人、评测/环境工程人员、多个对应学科的教师/领域专家，以及不参与该题制作的人类基线参与者。作者、仲裁者与基线作答者的关系逐题记录；不能将 AI 自检写成专家审查。

在两名主要研究/工程人员、教师按需并行参与且数据可得的条件下，可按 P0 约 1 周、P1 约 1–2 周、P2 约 2–4 周、P3/P4 约 2–3 周规划。它是资源假设下的排期，不是完成承诺；低产出率、缺材料或专家争议会延长。

仅正式人类首次作答就有 60+12=72 次。若每次平均 45 分钟，对应约 54 人时；作者制作、复核、双评、仲裁和修改另外计算。涉及教师＋开发协作的产物还需团队工时。真正限制规模的很可能是有效题与验收，而不是 API 并发。

## 15. 研究贡献、发布材料与保留意见

已有 TeachArena 覆盖教学判断、模拟多轮和 LMS 工作流，也包含保持构念的修题；不能宣称首次教育 Agent、首次闭环或首次不只判答案。[TeachArena v4](https://arxiv.org/html/2605.14322v4)

本项目应争取的贡献是：

1. 专家审查、正常工具条件和留出验证下成立的共同困难案例；
2. 忠实学生原作与教育产物运行语义的可核验成功标准；
3. 正确非标准解、有效新证据、科学一致性等能指导研发的诊断对照；
4. 公开筛选分母、无效题、已解决例和预算影响，提供可信的持续进展记录。

正式发布至少包括：任务/来源说明、核心及控制分区、作者参考和可接受替代解、验收器与负例、环境与工具版本、完整系统配置、原始输出与产物、重复及高预算结果、专家基线、评审分歧、污染与访问状态、更正记录。只能分享有权分享的材料；缺失项明确标注。

真实学生学习验证可以作为后续独立研究，不是为了给当前工程/诊断任务补一个笼统的“有效”标签。若核心始终没有足够困难，最诚实的结果是一个审计/可靠性 benchmark；不能仅靠名称将其包装成 Last Exam。

后续学科扩展可考虑基于史料的论证反馈、语言理解与可访问性、真实实验数据解释等；采用同样的专家可解、证据充分、可靠判分和完整 Agent 复测门槛。不能为了“教育全覆盖”提前将缺乏可靠 gold 的作文偏好或心理推断并入首版总分。
