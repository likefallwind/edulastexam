# Edu Last Exam 难题发现与方向机制计划

## 目标

Edu Last Exam 的难度目标是“对 AI 难”，不是把教育题目做成长，也不是把一次模型错误直接解释成真实学生难度。本阶段先把 37 个方向各自的失败机制、难度条件、可观察信号和控制条件写清楚，再从已有大规模 benchmark 结果中找候选题。

方向与机制索引见 [`direction_mechanism_map.json`](../../data/edu_last_exam_difficulty_mining_v1/direction_mechanism_map.json)。每个方向保留自己的构念；P01–P21 只作为解释轴，不作为题目分配目标。

## 证据路线

1. **既有逐题评测挖掘**：从只读的 `../edubenchmark` 中读取同一 suite、同一 benchmark、同一 item 的 scored JSONL，统计模型面板的全错、全对、分歧和覆盖情况。当前第一批覆盖 C-Eval 和 MOOCCube 先修题的 `mini_v2` 与 `frontier_v1`。
2. **题目与金标核验**：逐条回到原始题面、选项、答案、评分器和输入完整性，排除歧义、错误金标、解析/工具失败、多合法答案和重复 identity。C-Eval 的学科 Hard 不能替代逐题人类难度；MOOCCube 先修边是本地协议重建，不能冒充论文原题。
3. **机制映射**：候选题只进入与其失败机制一致的方向，且映射标记为 provisional。一个知识题的错误不能直接充当长期教学、学习效果或安全行为证据。
4. **保留与复测**：保留原任务条件；没有原题时，依据研究中明确的失败条件按机制自建，并在卡片中记录来源、必要输入、参考答案和关键错误。通过独立作者检查后，用未参与筛选的模型和必要的人类/教师证据复测。

## 难度证据的分层

|层级|含义|能支持的结论|
|---|---|---|
|文献中的失败条件|研究或公开任务报告了模型在特定条件下的失效|为什么这个机制值得测，以及需要保留哪些条件|
|历史模型面板错误|既有运行中多个模型对同一题错误|候选发现和复核优先级|
|结构难度字段|如 chance、约束数、概念数、order 变体|构造难度或分层变量，不是人类难度金标|
|人工/学生表现|独立教师量尺、学生作答或稳定人类数据|在题目和协议通过核验后，支持人类难度相关结论|
|冻结 benchmark 结果|预先固定题集、评分和 held-out 复测后的证据|支持发布范围内的 AI 难度结论|

当前生成的 `reports/difficulty_mining_v1/` 只属于第二层候选发现，不能写成“37 个方向已经找到难题”。`mini_v2` 是日常筛选，`frontier_v1` 是富集历史错误的 challenge selection，二者不做总体平均。全错候选也不能绕过题目/答案审查；例如 C-Eval 中的六阶群题已经显示，模型一致错误可能来自题干或术语歧义。

## 第一批完成条件

- 37 个方向都有机制、必要条件、观察信号、控制条件和排除项；
- C-Eval 与 MOOCCube 的已有面板结果按 suite 分开逐题索引；
- 输出只保留结构元数据和模型聚合统计，不复制回答、密钥或原始下载数据；
- 报告中明确 panel 覆盖、item identity、gold 稳定性和人类难度均需后续核验；
- 不修改 `../edubenchmark`，不把候选报告当作冻结 benchmark。

## 下一步顺序

1. 先人工复核 C-Eval/MOOCCube 的跨 suite 交集全错候选和结构上最难的 order/反向干扰项。
2. 修正题目 identity、金标和多合法答案后，加入 K12Bench、MathTutorBench、LongTutor 等有逐题产物的来源；对依赖 LLM judge 的 benchmark 单独保留 judge 稳健性字段。
3. 每个方向从机制证据中选择少量高信息量题目，补齐中性/反事实控制和可执行的评分协议；不要按“每方向固定三题”机械扩充。
4. 用未参与筛选的模型复测，报告方向内结果、错误类型和未测边界；只有在题面、金标、协议和复测都稳定后才进入冻结集。
