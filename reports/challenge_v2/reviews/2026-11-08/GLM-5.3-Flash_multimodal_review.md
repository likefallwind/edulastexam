# GLM-5.3-Flash 多模态试跑审计

日期：2026-11-08  
运行目录：`reports/eval/edu_last_exam_challenge_v2/_exploratory/GLM-5.3-Flash/20261108_03_multimodal/`

## 结论

这次运行的接口和多模态链路是成功的：34/34 个 prompt 返回，34 个 `stop`，无 API 错误；4 个图片 prompt 都收到了图像输入并生成了回答。它没有形成正式 benchmark 分数，因为本次没有自动 judge，也没有执行回答中生成的 HTML/SVG/代码产物。

按 reference 和题目检查标准逐项人工审计：

- **明确实质错误：2 个 prompt**：ELE-C2-01、ELE-C2-16。
- **局部问题：1 个 prompt**：ELE-C2-13 A，教学策略过于保守，但没有破坏核心判断。
- **核心判断正确：其余 28 个 prompt**，包括 02–08、09–13 B/C、15、17、18、21 的三个变体。
- **需要执行或渲染后才能定案：3 个 prompt**：ELE-C2-14、19、20。

因此不能把这次结果写成“32/34 通过”或一个正式准确率。更准确的表述是：**在文本和静态推理层面，GLM-5.3-Flash 只暴露出两个已确认的核心错误；但对产物生成类题目，执行层证据仍缺失。**

## 已确认的两个核心错误

### ELE-C2-01：把本题中合法的等权平均判成错误

模型正确算出了 A/B 线的阳性数量和最终概率，也正确指出 K4 的假阳性合并存在错误。但它把 K3 的 `(90% + 80%) / 2` 判为“没有依据、只是侥幸正确”，并将 K3 作为最早错误。

本题两个不合格群体的样本数恰好都是 1,200，因此这里的等权平均与按样本数加权完全相同；K3 在本题中应判合法。真正的首个错误是 K4，因为合格群体规模 38,800 和 58,800 不相等。模型没有把“通常需要加权”和“本题这一次等权恰好等价”分开。

这不是算术错误，而是**在审阅学生推理时把一般规则错误套到了具体分母相等的案例上**。这正是题目要测的证据敏感性。

### ELE-C2-16：把“设计不保证识别”和“这次观测不能识别”混在一起

模型主体的测量设计、共同偏移消去、差值误差界、合格点对 `(0,2)/(1,2)`、异常日志和迁移分析基本正确。但运行说明把重复测量 `x=2` 概括为“设计无辨别力，第二阶段将显示两模型均相容”。

这句话对设计保证层面过强。重复 `x=2` 确实不能保证在所有允许误差下识别，因为 M/N 的单点可行区间 `[7.6,12.4]` 与 `[9.6,14.4]` 有重叠；但本题教师返回的实际读数是 13.8。此时 M 的最大允许读数是 12.4，M 已被排除，N 可行，应该判定 N。也就是说：

- **事前保证**：重复 `x=2` 不合格，不能保证识别；
- **事后证据**：如果实际读到 13.8，仍然可以排除 M、支持 N。

模型在答案后半部分又正确算出了 `x=2` 的两个区间和 `13.8` 对 M 的排除，因此这是同一回答内部的协议分支矛盾。修订时应让重复点分支只把 P2（设计保证）记为不合格，B1/B2/B3 仍按实际读数执行。

## 其他观察

- **02–08**：两道图像题的读图和物理判断均正确。ELE-C2-08 B 额外计算了题目没有要求的“约 0.57 秒后再次绷直”，数值本身一致，属于无关扩展，不算核心错误。
- **09–12**：能够区分总体数量与分层比例、测量误差与系统边界、作品正确性与学生公开表达意愿，并能从 40 条历史记录中区分“无提示成功”和“提示后成功”。这些是本套题较重要的教育判断点，模型没有把代理证据夸大成能力结论。
- **13 A**：模型拒绝直接确认学生自己提出的“除以 1/8 等于乘 8”，比金标要求更保守。更好的做法是简短确认这个想法可行，再要求学生自行解释和验证；当前回答仍保留了独立尝试，因此是局部策略问题。
- **14**：学生 A/B 的差异化诊断总体正确，但生成的 HTML/SVG 没有实际渲染；此外题面中“第一次/第二次截去”与“同一整条、互不重叠”的关系需要人工确认，否则答案的相加解释可能存在歧义。
- **15、17、18、21**：核心代数、可识别性、错误模式诊断和公平评分判断均与 reference 一致。尤其 15 能发现原参数题答案键本身不成立，18 能发现原分数诊断题的选项碰撞。
- **19**：物理分段和数值修正正确，但 SVG 未打开检查排版与图层。
- **20**：静态代码符合分段 RC 模型、历史轨迹和重置语义，但尚未在浏览器中运行交互。

## 对这次试跑的含义

这套题已经能让当前模型在两个有意义的地方出错：

1. **具体证据是否足以支持一般性规则**：ELE-C2-01 测的是“不能只套一般原则，要看当前样本结构”。
2. **实验设计保证与实际观测解释的层次分离**：ELE-C2-16 测的是“不能把事前不可保证误写成事后数据不可判定”。

这两类错误都不是冷知识或故意刁钻的算术陷阱，而是教育工作中实际会造成错误反馈、错误评分或错误实验结论的判断失误。下一步若继续使用这套题，优先做的是：

1. 修正 ELE-C2-16 的重复点教师运行分支；
2. 补跑 ELE-C2-14/19/20 的真实渲染、浏览器和脚本检查；
3. 再用至少一个独立模型和一个 judge 复核这两个失败是否稳定，避免把单模型一次回答当成跨模型 benchmark 结论。
