Edu Last Exam：近两年证据与方案重审

研究与讨论稿 · 核查日期：2026-11-07 · 文献窗口：2024-11-07—2026-11-07。记录论文版本、实测模型、协议和数据可用性；不是系统综述或穷尽性检索。本轮未调用评测模型 API，未修改既有题库、代码、映射或结果。

结论：目标应是“专家能完成、结果有教育价值、成功可核验，而多数当前强 Agent 在正常工具条件下仍不能完成”的任务集。现有 12 题不能证明已经达到该目标。新证据支持先复测公开原例，再决定原创题方向；目前最值得投入的是忠实诊断与修复学生作业、科学上正确的可执行教学材料，以及有条件保留的证据驱动教学决策。
目标与证据标准原方案的问题可追索候选反证与筛除建议形态下一步来源与状态

一、先把“难”与“有意义”落实到可检查的条件

用户目标是寻找共同能力边界。全员失败可以成为正式挑战集的有效组成，不必为了当前模型排序而塞入大量中等难度题。容易题仍需要作为诊断对照，但不必计入挑战集主分。困难不能来自错误金标、缺失信息、隐藏措辞要求、任意加长任务，或禁止现实中正常可用的工具。

评价单位应是模型＋Agent 实现＋工具＋运行条件。一篇 2026 年论文可能仍测试 2024 年模型；一个叫 Agent 的系统可能只是一个角色提示。必须同时记录论文日期、模型标识、是否允许执行/检索/浏览器、是否有反馈后修复。本报告中的“作者报告失败”均不是本地复现结果。

必须成立的条件可核验要求不够充分的替代证据
教育价值指出真实使用者、具体工作、错误后果；需要忠实处理学习者证据或形成有效教学产物给普通数学/代码难题加“老师”角色
可解性领域教师/专家在相同可见信息与工具下独立完成；存在可接受参考结果及替代解出题者知道隐藏答案，或某模型偶然命中标签
可靠判分用反例、执行、数值/几何约束、原始证据及专家复核判断实质错误单一 LLM judge 的低分、唯一措辞、完整标签集合不一致
前沿难度多个不同家族的当前强系统在允许正常工具的条件下重复失败旧模型单次失败，或一个模型的总体均分低
研发指导能分辨感知、证据整合、诊断、行动、产物核验中的失败位置，并测试有效补救整题零分后给所有涉及能力都记低分

二、原方案：保留出发点，改变取题与验证顺序

复核材料包括 pilot 说明、taxonomy、判分合同、12 题原件、11 月 4 日设计稿，以及本轮前段已检查的模型原始输出与 adapter。

原设定具体问题建议
四类能力先定配额，再据论文概括出题论文“发现某能力薄弱”不表示简单改写后的题仍保留困难；也不能据此预标 frontier_hard先收集保留原材料与失败输出的案例；审题、复测后再归类。允许某方向暂时没有合格题
诊断、长历史、难度校准DT-001 将诊断信息写进输入；DT-002 用短摘要代替长轨迹；AD-001 提供统计结果，测的是解读统计，不能承担预测学生难度的 claim保留真实信息结构；将“已有数据的质量审查”和“未知群体难度预测”分开
评分稳健性作为首要难题源GR-002 已给空白卷 0 分，失败在反馈政策；GR-003 维持分数但少说一句理由，且原金标本身需复核。它们不直接证明受到操纵而错判基础抗诱导作控制；主任务要求能拒绝无依据争分，也能根据真实新证据改正错误评分
GR-001 只需将金标 5 改成 3原书写中的合计等式不能唯一证明两个幂值分别被算反；另有“忽略附注”与扣分标准之间的冲突暂列争议题，先澄清学生证据和评分语义，不能直接宣布修分后真实通过 10/12
任何 hard gate 失败即整题 0实质学科错误、遗漏理由、反馈风格可能被同等处理；严格规则不是难度效度只有会破坏任务用途的失败进入关键门槛。格式、风格与实质任务结果分开报告
纯文本先行，图像和交互一律暂缓降低实现成本，也提前排除了真实手写作业与可执行产物中较有希望的困难重新开放多模态和运行环境；是否入选由教育意义、可核验性和实测难度决定
把两次 AD-002 判分差异解释成同答案 judge 翻转已检查的两个运行有不同模型回复，也有 judge 身份差异区分生成波动与判分波动。若研究 judge 稳定性，必须固定同一回复

两模型原始记录均为 12 项完成、9 项通过；这是原合同下的探索结果，不是“真实教育能力 75%”。已发现的题目争议使有效通过率尚不能直接重算。adapter 也需在后续实验前补核判分身份/缓存与格式规则，但本轮不修改实现。

原方案的文献分母也要纠正：EduWild 的 53.8% 是 900 条历史会话中的流程遗漏比例，导出时的模型配置不能代表每条旧会话；Will It Teach as Intended? 的 59.3% 是 27 个最终 bot 配置中 16 个通过目的对齐评价，不是某个模型的回复通过率。它们支持研究部署问题，尚不能直接支持当前强 Agent 的失败率。

需要撤回的实施预判：直接追加几道更复杂的申诉裁决、批改或命题修复题，还没有足够依据。申诉更多轮、合同更长不自动产生实质难度；合理工具和重新计算可能直接解决。应把“复测文献原例”放在原创命题之前。

三、最值得追踪的原例：失败在哪里，证据又到哪里为止

1. PyMETA：同一份学生代码中，被首个错误遮住的后续错误

可优先取原例 2026-06 首发，09-15 v2。真实 Python 提交 48,646 份。GPT-5.5 等四个近期模型在首错误分类上 macro-F1 已达 87.5–93.8%；精选 97 份多错误提交的 exact-set 为 43.3–48.5%，但 sample-F1 仍约 79–81%。可追索样本包括 Sample_Index 1885 与 3375。

价值在于修复顺序可能暴露新错误，教师需要解释真正阻断学习的原因。限制是 gold 只覆盖一条人工修复路径，不保证穷尽；模型未获执行工具。不能把多找一个合理错误算失败，也不能把标签集合不完全匹配等同无效辅导。论文 · 97 项标签 · 官方代码。

2. HG-Bench：学生到底在哪一页、哪一步写了什么

真实共同失败，数据待发布 2026-06 / EMNLP 2026。500 份真实 K–12 作业中，115 份在九种零样本设置下均未达到答案区域 F1≥0.5。官网 Case 2 是页号错配与跨页步骤乱序；Case 3/4 是过度切分和合并步骤。

这直接影响反馈是否指向学生原来的作业。但原测是单次 VLM 定位，不是允许裁剪、OCR 和回看检查的 Agent；边框粒度也有标注约定。官网及仓库目前仅提供案例、脚本和少量示例，完整 500 份数据仍待发布。应关注证据归属导致的实质误批，不单纯以框坐标误差定义教育失败。论文 · 官方案例与数据状态。

3. LeanPRM：流畅证明尚未完成目标，却被当作正确

先独立重审金标 2026-10-13 首发，11-03 v3。200 个证明里，四个商业模型的原始运行共同错标 26 个。附录 C Figure 7 中，论证只建立求和不等式，未完成要求的两个不同零点，模型仍接受。

但无人工 gold；作者用另一模型审计时，两大“数学错误”类各有 13/30 被判为数学上成立，可能是形式化失败。该审计本身也不是人类真值。26 个共同错误只能作为候选，不能直接入库。另“全步骤标签一致”不同于正确指出关键缺陷；正式任务必须由专家重验自然语言证明与形式表达。论文、Table 1 与 Appendix C · 项目入口。

4. 物理批改：数值相近掩盖受力对象错误

具体原例，版权限制 2026-03 首发，09-26 v3。Figure 16 的 Q3 将塞子的额外受力算成整个壶底的额外受力，结果约 5882 N，参考为 5760 N；即使给出参考解，五模型仍满分。

它提示要检查物理对象和推理，而非只看公式流畅或数字接近。但答卷由模型生成，非真实学生；原题因版权只公开改写说明。同论文结构化评分总体相关较高，不能据少数错例宣称批改普遍困难。该例适合复核与机制调查，改写后需重新建立难度证据。最新论文 §V、Figure 16。

5. InteractScience：能运行的科学演示仍可能教错

可执行原例优先 2025-10 首发，2026-05 v2。150 个科学交互任务、779 项功能测试；GPT-5 的 PFT 功能测试通过率 39.47%，PFT 功能测试全部通过的题目比例 16.08%；两者均不包含全部视觉质量检验。附录弹簧—质量—阻尼案例表现出视觉与科学含义脱节。

仓库含任务、测试、参考图和输出；原协议是一次代码生成，不能作为今天带浏览器调试的代码 Agent 通过率。要进一步验证参数变化时数值、图形和解释是否一致，不能只查 DOM、截图相似度或美观。论文 · 官方代码与材料。

6. TeachArena：已经有人在做完整教育工作流，不能忽略竞争基线

环境可借鉴，需逐题筛 原 EduAgentBench 已在 2026-09-29 v4 更新为 TeachArena：354 项、17 个模型。最高工作流平均 reward .704；6 个长流程任务、跨 17 个系统的平均 reward 为 .321。这些是 reward，不是通过率。

MM-04 要根据历史学习记录修改现有材料并配练习，文中 GLM-5.1 生成泛化新材料而失败，GPT-5.5 成功；EXAM-REV-03 要改微积分试题参数同时保持知识点和答案有效。公开数据含 mock LMS 状态和评估代码。不能再以“教育判断＋多轮辅导＋LMS 流程”本身作为新颖性；也不能沿用早期版本模型/任务数。最新论文 · 数据和环境。

7. TutorCaseBench：原方案有依据，但“复现既有有效干预”不等于唯一正确行动

保留教学决策候选 2026-10-22。1,560 项开放回复中，Opus 4.7 / GPT-5.5 分别有 55.8% / 54.7% 至少满足一条案例 rubric。输入是六轮合成既有对话，输出一次续写或长期计划；“长期”不是实际执行数周。

Table 2 分析的 50 个全模型失败样本中，有学生因误认作业错误而拒绝展示；模型安慰“犯错正常”，案例策略却是先核查作业正确性。这比泛化的“要有同理心”更有诊断价值。

论文确实测试近期强模型；但 rubric 来自隐含的历史干预和比模型可见内容更完整的案例背景。需要检查：当前可见证据是否足够、其他合理策略是否被排除。它可以支持寻找复杂教学案例，不能把隐藏策略写进 system prompt 后再称测诊断，也不能将一次计划文本当作学习增益。论文 §3–5 · 官方数据。

三条线不应预分固定题额，也不需要同时做大。如果带工具复测后 A 很容易、B 仍困难，就集中 B；若某类教师也无一致可行答案，则退回研究问题，而不是靠收紧 rubric 入库。

区别于已有工作的贡献应是什么：经过专家和判分器审计、仍能难住近期完整 Agent 的教育任务；每题保留真实证据结构、正常工具条件和可解释失败机制。仅换一个教育名称、重组现成低分 benchmark，或把公开题做同义改写，都不足以构成这项贡献。

按仓库历史 D 体系，A 主要涉及 D11 分步评分、D12 错误定位/纠错、D06 多模态过程、D09 编程教育问答；B 涉及 D22 教学可视化、D23 交互科学演示；C 涉及 D13 辅导、D17 认知诊断。它们属于任务需求标签，不自动形成 P01–P21 的直接测量分数。本报告不修改当前 v7 映射。

六、下一步的具体顺序与停止条件

  1. 建立 12–18 个原例的复核池。这是工作量上限建议，不是正式题量承诺。首先从 PyMETA、InteractScience、TeachArena、TutorCaseBench 取可获得的原例；LeanPRM 待重审、HG-Bench 待材料。每例保存原题、原材料、作者失败输出、来源版本、目标、金标依据、数据/许可状态。公开材料先用于发现机制，不直接伪装成全新测试集。
  2. 先验证题和判分。领域教师/专家独立完成并互审；关键争议要裁决。判分器必须接受至少一种正确替代解，并拒绝有关键错误的近似交付物。若无法区分有效替代方案和目标失败，该例暂不能成为硬门槛题。
  3. 先用两个强 Agent 做淘汰性复测。具备任务所需的终端、Python/CAS、OCR/裁剪、浏览器和运行反馈；允许正常自查和迭代。记录模型、harness、工具、版本、耗时和费用。依照仓库规则不人为设模型输出 token 上限。公开 ground truth/测试答案不作为 Agent 检索材料；内部核验测试与被测输出隔离。
  4. 只有幸存候选才扩大模型面板。例如五个不同家族/系统，分别运行三次，报告逐次完成数和错误类型。若至少四个系统反复存在实质失败，可以成为“该冻结面板下的共同难例”候选；小样本不能推断全球 80% Agent，更不能称未来不可解。至少保留一个未参与出题的系统或后续版本复验。
  5. 围绕验证过的失败机制原创。由作者/教师开发新的独立案例，保留实际困难，避免仅替换数字或表述；自建题沿用仓库既有出卡、编写、导出、自检与专家复核流程。记录真实来源、经转换的案例和专业挑战的区别，随后冻结第一版。
失败仍有价值的停止规则：若充分工具、清楚输入或可靠 rubric 使某类原例普遍通过，就将其转作控制/回归案例；不要通过禁工具、隐藏信息、扩大隐藏要求把它重新“做难”。若一轮复核后没有可信幸存案例，结论就是这些方向尚不支撑 Edu Last Exam，应改变任务来源，而不是继续堆题。

如何计分，才不会为了零通过制造零分

主结果报告实质任务完成率，关键错误需能说明为什么破坏教学用途。另报正确作业误伤率、关键错误漏检、证据归属、有效修复、产物科学一致性以及运行成本。多项必须同时成立可以合理，但每项都应有独立教育理由；微小格式问题和风格偏好不应触发教学失败。

难度筛选可以采用多数系统失败，不要求模型间形成漂亮排名；诊断对照单列。原协议成绩与带工具成绩分开，不把 F1、reward、rubric 均分都经 0.5 阈值变成同一种“没通过”。长期学习效果、延迟保持和迁移仍是另一个需要真实学生与研究设计的测量层。

八、来源使用与状态说明

核心证据只采用上述时间窗内的论文、作者项目页和官方代码/数据。优先核对最新版本及当前开放状态；检索结果和作者自称的“frontier”不等于当下最强系统的独立证明。对论文转述均保留协议边界。没有下载或运行这些新 benchmark 的完整数据集，不能把“发现公开入口”写成本地复现完成。

本报告还参考了近两年的 Humanity’s Last Exam 与 GDPval 的专家任务与交付物评估方法；它们是方法参照，不构成教育能力证据。GPQA、早期 Dynabench 等窗口外工作不作为本轮文献依据。
