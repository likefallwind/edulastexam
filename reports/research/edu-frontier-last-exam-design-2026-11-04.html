Edu Last Exam：高难度、高区分度与教育指导作用设计讨论

讨论稿 · 2026-11-04 · 不改动现有 frontier_v1 正式题单

调研范围：HLE、FrontierMath、Agents’ Last Exam、GPQA、TutorBench、TutorMoments、EduAgentBench、EduMARS，以及本仓库选题与结果证据。

核心判断难度不等于区分度。全员失败题几乎没有当前模型排序信息，只适合做前沿能力探针。
推荐形态一个构念蓝图、四类任务表面、三种题目用途；不做单一总分。
指导作用来源对照条件、消融实验、重复运行和失败归因，而不是低分本身。
覆盖判断需要新建评测 现有公开证据可复用，但不足以组成已验证的教育终局考试。

一、结论先行：应该做什么

推荐：把目标定义为“AI 教师与教育智能体的前沿能力评测”，而不是“更难的学科题合集”。闭式专家难题保留为基础与推理 track；真正的教育特色放在学生作业诊断、适应性辅导、长历史利用和教师工作流执行上。

最终同时交付两个产品：

  1. Edu Frontier Profile：分能力报告严格完成率、诊断性部分分、重复运行可靠性、人机基线、成本与不确定性，用于模型/系统比较。
  2. Capability Gap Atlas：回答“在什么条件下、哪些系统、在哪类教育任务上、因为什么机制失败、哪项干预可能有效”，用于指导研发与产品治理。

不建议把全员失败率当作唯一入题标准，也不建议把各 benchmark 归一化后再平均成一个“教育总分”。如果必须有榜单，应提供分 track 的区间/层级排名和不可补偿的安全门槛。

二、场景解释与评测边界

要素本讨论采用的保守假设
被测对象既包括基础模型，也包括“模型 + prompt + 工具 + 记忆 + 学生模拟器 + agent harness”的教育系统；两类结果必须分开标识。
输入题面、真实或授权的学生作业图像/文本、评分量规、学习历史、对话、课程材料、LMS 状态与工具。
输出答案与依据、错因诊断、评分与反馈、下一步教学动作、多轮辅导行为、修改后的教学产物或环境状态。
主要使用者模型研发团队、教育研究团队、评测方和教育产品团队；不直接把分数当作学校采购或学生高风险部署认证。
风险级别高。涉及未成年人、教育评价、心理健康与公平，且“AI 做不好什么”的公开结论会影响研发投入和产品部署。
明确不测/不冒称静态或模拟任务不直接证明真实学习增益、延迟保持、迁移、教师采纳或课堂整体效果；这些需要独立实证研究。

三、对现有 frontier_v1 的判断

现有套件并不只是“大家都做错的题”。冻结报告中，4,089 道抽样题包括 27.8% 全员失败、67.3% 有对有错、4.8% 全员通过，另有 830 道固定全保题，总计 4,919 道。方法文档也正确指出：全员失败用于未来边界，有对有错题承担当前排序。

因此，问题不是简单地把比例从“全错”改成“混合”，而是当前的选题起点和验证链仍然不够：

当前做法能说明什么还不能说明什么
继承 mini_v2 的 benchmark 配额，再按模型结果选题保留来源与内部标签覆盖，形成可复现的挑战集教育重要性是否优先、每个能力是否有足够独立任务、哪些能力最值得研发
把不同 benchmark 的信号截到 [0,1]，以 0.5 判过/不过提供统一的数据处理入口accuracy、QWK、pairwise win、rubric 均值和严格结构匹配并不共享同一个“掌握”含义
用选题面板的模型分歧表示区分度在当前面板内确实更容易出现模型差异差异能否在留出模型、模型家族、重复生成和换裁判后复现
保留全员失败题提供未来 headroom 和错误发现入口失败是否源于教育能力，还是坏题、解析、图像、裁判、过严格式或不可解条件
保留原生 benchmark 结果和 profiles有逐任务诊断材料尚未形成跨任务的失败机制分类与可检验研发建议
公开旧题反复使用低成本、可比较抗污染、未来版本等值和滚动更新能力不足

本地 BHI 试验也给出了同样的统计警告：8 模型面板上，随机移除模型、嵌套面板和小噪声都会改变不少名次，所以应使用宽层级和稳定性分析，而不是精细排名。

现有资产的合理去向：Full 继续作校准权威，mini_v2 继续作常规筛查，frontier_v1 保留为实验性挑战与候选证据池。新方案应另立版本，不把旧套件直接改名成“已验证的 Edu Last Exam”。

四、外部方法真正值得借什么

Benchmark已记录的方法对我们的启示不能照搬之处
Humanity’s Last Exam专家原创、模型筛难、研究生级复核、闭式可判答案、公开+私有题、发布后审计与错题悬赏完整题包、专家网络、抗检索、自动评分和持续纠错都很重要模型失败筛选会偏向当前模型弱点；作者明确提醒近零分段的小变化不是强进步证据，闭式学术题也不等于开放研究或教学能力
FrontierMath按背景、洞察时间和执行时间定义难度；原创、防猜、计算可验证、领域专家盲审、少量公开样例先定义专家能力和难度层，不以“所有模型全错”代替构念定义可计算唯一答案更适合数学，不足以覆盖教学判断、互动与育人价值
Agents’ Last Exam（ALE）真实专家完成过的职业项目、长时程 GUI/CLI 工作、最终交付物验证、保存轨迹和成本教育版应测完整的证据→诊断→干预→产物→沟通→核验链，而非只测下一句回复工作流完成不等于学生学习有效；系统/harness 差异也不能直接归为基础模型差异
GPQA作者—同域专家—修订—第二专家—高技能非专家检索测试；专家正确且非专家难解的联合标准模型筛难之外，加入真实人类可解性和专家评审激励学科专家可答不等于教师能教；需要教师/导师基线而不是只用学科专家
TutorBench专家编写辅导上下文与逐题 rubric；至少 3/5 强模型低于 50% 才保留；多模态学生作业、细粒度二值 criteria与我们目标最接近：能定位“误解学生、未给替代解释、提示泄题”等具体失败仍是固定历史上的单轮最终回复；难度筛选不能替代动态适应和学习效果
TutorMoments真实一对一辅导 transcript，教师标注关键教学时刻，模型接管并进行多轮 replay；关注脚手架、认知挑战和过度帮助把“何时帮助、何时忍住不帮”变成可测决策，而非只评语言质量模拟学生和关键时刻选择会塑造结果；被刻意选出的“原导师本可做得更好”的时刻不能直接用于人机优劣结论
EduAgentBench教育判断、情境辅导、Canvas 风格工作流三表面；结果断言、过程约束、严格通过与 dense reward 并行可直接借鉴三层任务表面与“完整合同通过 + 部分进度”双报告模拟环境不是部署认证；mock learner、裁判和弱模型迁移探针都不能替代真实学生研究
EduMARS真实中文 K12 作答、手写与混合布局、教师步骤量规/错误类型/关键点标注，同时评最终分和评分过程中文真实学生材料与过程性评分是高价值任务来源接入前仍需核对许可、数据协议和可复跑结果，不能只凭摘要宣称本地可用
SWE-bench Verified 退役审计审计 138 道 o3 在 64 次运行中不能稳定解决的任务，每题至少 6 名工程师复核；该难例子集 59.4% 存在实质测试或题述问题全员失败首先触发审题，不是自动入题。最难例子需要更严格的人类审计59.4% 只针对这个刻意选择的难例子集，不能外推到完整 SWE-bench 或其他 benchmark

五、先写“要支持的主张”，再写题

蓝图的基本单位不应是旧 benchmark，而应是“教育上重要、可以被证据支持或否证的主张”。建议第一版优先支持六类主张，并映射现有 D01–D24 场景语言与当前 P01–P21 测量模型。

核心主张/任务表面主原子能力当前 P 映射为什么有教育指导价值
读懂真实学生作业并正确定位、解释错误D12 学生错误定位；D06 多模态数学过程；D11 分步评分P03、P11、P12区分“看不见/读错”“会做题但不会诊断”“能定位但不能解释误概念”
根据学生状态选择并执行下一步教学动作D13 苏格拉底式引导；D12 纠错反馈P15、P17区分知道教学原则、生成一句好回复、在连续互动中真正执行之间的 knowing–doing gap
利用长历史形成学习者画像并适配教学D17 认知诊断；D15 学习规划；D16 知识追踪（次）P02、P14、P15、P16检验模型是否真的使用历史，而不是对任何学生都给同一套看似个性化的回答
在教师工作流中完成可核验的专业交付D24 端到端系统能力；D19 课堂话语（次）P09、P15、P17暴露证据查找、工具调用、状态维护、目标对齐、漏项与完成前未核验等 agent 失败
在普通与挑战情境中保持安全、边界、适龄和公平D21 教育安全；D24 系统边界P10、P18、P19、P20、P21防止学科/教学高分补偿安全失败；区分漏报、过度干预、不当关系和身份反事实差异
保持学科与过程正确、校准和可验证性D05 高阶数学/复杂推理；D14 教学法知识（次）P05–P08、P13 等作为门槛和对照，防止把教学评分差异其实归因于题目本身做错

次要能力：D14 教学法知识、D16 知识追踪、D19 课堂话语、D22 教学可视化、D23 交互科学演示。它们可以进入后续扩展，但第一版不宜为了“全覆盖”牺牲每个主 claim 的任务数与验证深度。

单独证据层：learning gain、delayed retention、transfer、teacher adoption 必须与模拟 benchmark 分开。可以用小规模真实学生随机/准实验和教师采纳研究对高优先任务做外部效度验证，但不并入同一个题库总分。

六、三类题目用途：不要把它们混成一个分数

题目用途经验表现主要功能如何处理
锚点/控制题多数强模型通过，或用于最小配对对照检查基础门槛、回归、跨版本连接；给对照实验提供基线保留但不奖励“越难越好”；饱和后可降低公开排序权重
区分题不同系统有稳定、可复现的 outcome 差异，而非一次性随机分歧当前模型/系统排序与能力画像必须在留出模型、重复运行和裁判复核后进入主排序集
前沿边界题当前系统普遍失败，但教育价值高、题意有效、专家可完成、评分可靠展示未来 headroom，形成研究挑战不承担当前模型精确排名；单独报告解决率与首次突破
待修/淘汰题失败伴随题意歧义、裁判分歧、不可解、格式漏洞或基础设施错误改进数据与评测器修复后重新走完整验证；不得为了低分而保留

这些是用途标签，不是题目质量等级，也不需要在命题前强行规定全库比例。命题池可以先覆盖连续难度，试跑后再按用途归档。

建议的入题流水线

  1. 构念审查：写清目标 claim、教育重要性、目标人群、任务条件和不希望测到的混杂因素。
  2. 人类效度审查：作者提供完整解与量规；独立专家实际完成/复核，教师检查教学真实性；作者根据反馈修订。
  3. 评分器审查：优先规则/环境断言；开放任务使用证据锚定的分析式 rubric，做人工双评和裁判校准。
  4. 模型试点：多样模型家族和 agent 配置参与；选题面板与最终验证面板尽量分离。
  5. 失败审计：重点审查全员失败、裁判分歧和异常格式失败，先排除坏题与不可解任务。
  6. 留出验证：检查新模型/新家族上的难度与排序贡献、重复生成稳定性、judge-by-model 交互和污染风险。
  7. 归档：锚点、区分、前沿或待修；保存不可变版本、题目/量规/裁判 hash 和变更原因。

每题/每任务族的完整题包

至少包括：输入材料与来源、授权/隐私状态、目标构念、教育重要性、参考解或理想工作流、可接受替代方案、分析式 rubric、硬门槛、常见误概念、预计教师时间、失败标签、对照/消融条件、公共/私有属性、版本和审查记录。专家报酬应奖励质量、独立可解性和评审贡献，不能只按“难住模型”付奖金。

七、让结果具有指导作用的关键：对照与消融

单题低分只能产生现象，配对条件才能帮助定位机制。建议把对照直接写进任务族，而不是结果出来后再拼凑解释。

对照/消融可分离的机制可能的研发或产品行动
同一份作业：手写图像 vs 经人工核验的文字/结构转写视觉感知/OCR/空间 grounding vs 后续诊断与教学多模态训练、版式/笔迹处理、视觉解析模块；不能笼统归因于“不会教学”
同一题：独立解题 vs 判断学生正误 vs 定位错误 vs 解释误概念学科能力 vs 教育诊断深度学生错误过程数据、误概念监督、诊断专项训练
同一情境：选正确策略 vs 生成一句回应 vs 多轮执行教学知识、生成能力和交互执行之间的差距互动训练、长期策略控制、学生模拟器与真实 replay；不能只增加教学法选择题
正确历史 vs 打乱历史 vs 无关历史 vs 无历史是否真正利用学习者证据，还是泛化的“个性化措辞”记忆表示、证据检索、历史利用训练；若分数不变，不能声称实现个性化
静态学生回复 vs 动态学生反应/反事实学生一次性答案质量 vs 根据反馈调整的适应性多轮 policy、学生状态跟踪、交互式安全与教学策略
无工具 vs 检索/计算/课程库/LMS 工具知识推理瓶颈 vs 工具选择、结果整合、长程状态与恢复工具调用、agent workflow、完成前核验；分别报告模型与系统增益
单次尝试 vs 独立重复 3–5 次会不会做 vs 是否稳定可靠；随机成功与真实能力差异自校验、重试策略、过程约束；部署不能只看 best-of-k
风险/正常、身份反事实、直接/多轮施压漏报与过度干预、公平差异、边界保持安全门槛、教师复核、转介策略、公平修复；不能由其他高分补偿

Capability Gap Atlas 的证据等级

等级可以怎么说需要的证据
L1 观察“这些系统在这道题/这次运行失败了”保存预测、评分和运行配置；不作广泛能力结论
L2 稳健缺口“在该任务族和协议下，多个系统稳定弱于门槛/人类基线”多任务、多模型、重复运行、人工效度与裁判校准、不确定性区间
L3 机制缺口“失败主要与视觉、诊断、历史利用、交互或核验机制相关”预注册的对照/消融显示预期效应，并排除主要替代解释
L4 干预验证“某类训练、检索、工具或 guardrail 能改善该缺口”干预在留出任务上改善目标分，同时不损害正确性、安全和其他 gate

合格结论的示意（格式示例，不是实测结果）

“在协议 C、系统集合 S 和任务族 T 上，严格完成率为 M［区间］，同条件教师基线为 H。手写与准确转写之间的差值为 Δ₁，正确与打乱历史之间的差值为 Δ₂；主要失败标签为 F。该证据支持/不支持机制解释 R，建议优先验证干预 I。结果不外推到真实学习增益。”

这比“AI 还不擅长个性化教学”更有指导意义，也更不容易误导。

八、怎样获得真正的高区分度

设计项推荐协议避免的错误
难度与区分度分别记录任务通过率和跨系统稳定差异；主排序题覆盖中间成功率与多种 response pattern，前沿题单列把全员失败当作既有难度又有当前区分度
面板覆盖不同模型家族、开放/闭源、大小、工具配置；选题与验证分开，做 leave-one-family-out每个 benchmark 用不同且过小的面板，又把同面板分歧当外部效度
重复运行试点至少 3 次，波动大时增加；报告 pass@1、passk（k 次都成功）和逐任务成功分布，pass@k 另列用 best-of-k 的成功冒充部署可靠性，或把随机分歧当稳定差异
严格通过与部分分完整合同 pass 与 checkpoint/rubric dense score 并行；内容正确、安全、指定产物修改可作硬门槛让“写了很多好内容”补偿错误评分、危险行为或没有完成核心动作
原生指标保留 QWK、Macro-F1、rubric pass、环境通过率等原生含义，按 track 报告把异质信号统一按 0.5 切成同一个“教育掌握”
不确定性按任务族 cluster bootstrap；给模型差值和分层结果区间；小样本只报宽层级把同一任务族的变体当独立样本，放大有效样本量
排名稳定性留出模型复验、模型家族留一、题目族留一、裁判交换、运行噪声与缺失处理压力测试发布没有区间的精确总名次
测量模型早期用描述统计、对比和稳定性；积累足够多异质系统后再评估 IRT/垂直等值用个位数或十几个相关模型硬拟合复杂 IRT，制造精确幻觉
成本与系统身份记录 token、时延、工具、retry、token 预算、裁判和 harness；基础模型 track 与系统 track 分开把 agent scaffold 的提升全部归给模型，或忽略昂贵重试带来的分数

十二、可执行的试点方案

阶段 A：先做 60–90 个任务族，不先追求 5,000 道

  • 围绕 6–8 个高价值 claim 建题，每个 claim 有足够独立任务族；不以旧 benchmark 配额为起点。
  • 覆盖四种表面：闭式专家判断、真实材料诊断、多轮适应辅导、教师 agent 工作流；安全与公平作为贯穿条件。
  • 每个任务族至少有一个对照条件或清晰失败标签；保存教师参考完成和评分证据。
  • 现有 frontier_v1 只提供候选：mixed 项进入稳定性复验，全员失败项先审题，固定全保项回到相应 gate/覆盖角色。

阶段 B：人类效度先于模型难度

  • 作者 + 独立学科专家 + 教师/导师审查；用于人机差距结论的任务需同接口、同工具、同时间预算的人类基线。
  • 所有边界题和预注册的随机校准子集进行人工双评；报告分歧、量规修订与裁判一致性，而非只报一个 judge 分。
  • 模型试点使用多样系统，独立重复 3–5 次；保存完整轨迹、产物、成本和失败类型。

阶段 C：用留出证据决定正式发布

  • 在新模型/模型家族上复验题目难度、区分贡献和 judge-by-model 交互；只发布宽层级与区间。
  • 根据试点扩大有信息量的 track，而不是机械扩大所有 track；公开开发题与私有滚动评分题分离。
  • 公开 Gap Atlas 时，把每条结论标为 L1–L4，并附适用条件、未知项和可复现证据。
试点验收不是“均分足够低”。应至少满足：教育重要性明确、独立专家有效、评分可靠、留出系统上有稳定信号、失败机制可解释、隐私与污染协议可执行。

十四、额外风险与发布纪律

  • 构念漂移：难度高不代表教育价值高；专家冷僻知识、格式苛刻和长 rubric 都可能制造伪难度。
  • 裁判可靠性：开放教学评分需窄粒度、证据锚定 rubric、人工双评与换裁判复核；目标模型与裁判相同或同家族时要披露。
  • 多模态 grounding：必须保留图像与转写对照，否则“教学失败”可能只是读图失败，反之亦然。
  • 学生模拟器：模拟学生本身是测量工具，需要与真实 transcript/学生子样本校准；不同模拟器结果不能无条件横比。
  • 污染与反馈泄露：公开题、私有题、滚动题和反复提交 leaderboard 都可能泄露；限制详细分数反馈并监测公共/私有差值。
  • 隐私与授权：未成年人真实作业、对话和历史需要授权、去标识化、最小化访问和再分发限制。
  • 教师监督：所有高风险分数都应理解为人机协作证据，而非取消教师复核的理由。
  • 学习效果鸿沟：回复质量、模拟学生进步、弱模型 transfer 和真实学生延迟学习是四种不同证据，不能相互冒名。
  • 维护预算：HLE 与 FrontierMath 的审计/修订经验说明，专家命题加一次评审仍不够；需要错误悬赏、抽查、版本 changelog 和继任题池。

十五、建议我们讨论并拍板的四件事

  1. 主目标：我更推荐“AI 教师/教育智能体能力前沿”，闭式难题作 gate，而不是另做一个学科知识 HLE。是否同意这个定位？
  2. 首批三大 claim：建议先做“真实作业诊断”“关键教学时刻的多轮适应”“教师 agent 完整工作流”。长历史利用可作为贯穿对照。哪些最符合团队希望对外释放的信息？
  3. 人类与数据资源：是否能获得授权的真实学生作业/transcript、独立教师审题与双评？这决定第一版能做到“真实教育任务”还是只能做“高质量模拟任务”。
  4. 首要交付：建议先发布“能力边界与失败机制研究报告 + 小规模私有 leaderboard”，再扩大公开榜；是否接受不做单一总分？
一句话方案：以教育构念为蓝图，以专家有效任务为基础，以留出模型上的稳定差异做排序，以全员失败但有效的任务做前沿探针，以对照/消融和重复运行把失败转化为研发指导。
